Основание:
* ТЗ «Единая система управления предприятием общественного питания „ЦЕХ“» v1.0 от 20.10.2026,
  раздел 2 и этап 0 раздела 17;
* ТЗ v2.0 «Минимум действий персонала • Пищевая безопасность • Актуальные нормативы РФ», раздел 13
  и этап 0 раздела 15.

* зависимости;

* план миграции;
* состояние резервной копии.

Слияния архивов поверх друг друга не было. MON CHEF лежит отдельно (`monchef/`), ЦЕХ — в `gas/`.

## 4. Данные из присланных книг

* **Единый каталог MON CHEF.** 1549 ProductID: 1218 из основной базы и 331 из добавочной.
  * Из них 1450 уникальных названий, 88 групп точных дублей (187 строк), 38 похожих пар, 50 конфликтов ID.
  * Все дубли помечены «не объединять автоматически» — это совпадает с ТЗ (AT-05).
  * Пищевая ценность: «НЕ ПРОВЕРЕНО», источники не подтверждены.
* **Шаблон технормативов.** 10 845 строк: 7 операций × 1549 продуктов.
  * Заполнены 3 строки (язык говяжий, источник ChefExpert, «не утверждено»), остальные пустые со статусом «НЕ ПРОВЕРЕНО».
  * Нормы потерь не выдумывались. Это и есть основа для правила ТЗ «коэффициент только с подтверждением» (AT-06, AT-07).
* **Реестр источников.** 9 записей: 5 шаблонов категорий, 3 справочных (ChefExpert), ТР ТС 022/2011.
  * Уровни доверия: официальный документ / документ производителя / справочные данные / контрольная проработка / внутренний норматив.
* **Журналы J01–J53.** Реестр с типом заполнения и пересечениями, например J01 ↔ J25 ↔ J42.
  * Формы J39–J53 ручные, по образцу.
  * Повторяющиеся журналы нужно свести в один источник записей с несколькими печатными формами. Так уже работает MON CHEF: «одна запись → все формы».

## 6. Платформа — варианты для решения (блокер Б-3)

| | А. Новая платформа по ТЗ | Б. Остаться на Apps Script |
|---|---|---|
| Стек | TypeScript (Next.js) + PostgreSQL + очередь + файловое хранилище | Apps Script + Google Таблица (код MON CHEF как основа) |
| Многие организации, email, MFA, изоляция (AT-01, AT-02) | Штатно: `tenant_id` в каждой записи, транзакции | Отдельная таблица на организацию или фильтры; регистрация по email делается вручную; MFA нет |
| Транзакции, конкурентность | Есть | Одна блокировка на скрипт; лимит 6 мин на вызов; квоты на чтение |
| Перенос механики MON CHEF и ЦЕХ | Переписать логику модулей на TypeScript по описям; данные — миграцией | Дописать функции ЦЕХ в код MON CHEF |
| Срок до первого рабочего контура | Дольше: этапы 1–3 ТЗ строятся заново | Быстрее |
| Соответствие ТЗ | Полное | Частичное: разделы 3.1, 13, 15 и AT-01/02/18 под вопросом |

Рекомендация: **вариант А**.
* ТЗ v1 прямо описывает SaaS для многих организаций.
* ТЗ v2 §13 запрещает делать Google Таблицу единственной транзакционной базой без доказательства,
  что её хватает. Для журналов и партий нескольких организаций с конкурентной записью такое
  доказательство получить не удастся: одна блокировка на скрипт, 6 минут на вызов.

Механика MON CHEF и функции ЦЕХ переносятся как бизнес-правила по описям: в коде ничего не
теряется, меняется только платформа. Таблицы остаются для справочников и выгрузок, как разрешает v2.
