## Основание и метод

**Основание:** ТЗ 3.0, §23.1 и этап 0 §30. До новой разработки нужно сверить фактическую рабочую версию с требованиями.

**Что проверено:**
* миграции 001–045;
* серверный код `platform/src/server` — около 11 тыс. строк в `ops/`;
* API `platform/src/app/api/v1`;
* 36 разделов интерфейса;
* 43 файла автотестов, 315 тестов — проходят.

**Ограничения метода:**
* Оценка «есть / частично / нет» сделана по коду и схеме БД.
* Приёмочные протоколы по §29 ещё не проводились.

**Прежние аудиты:** аудит этапа 0 по ТЗ v1/v2 лежит в `docs/ЭТАП_0_АУДИТ.md`. Опись старой версии на Google Apps Script — в `docs/ОПИСЬ_ЦЕХ.md`. Эти документы не изменялись.

**Обозначения:**
* ✅ — реализовано;
* ◐ — частично;
* ✗ — нет;
* ⚠ — противоречит ТЗ 3.0, нужно решение.

## 4. Противоречия с ТЗ 3.0 — нужно решение заказчика

**П-1. Касса и зал.** В платформе работает кассовый контур: заказы, оплата, возвраты, смены кассы. Он перенесён из архива `tsekh-kassa` по ТЗ v1/v2. ТЗ 3.0 (§1.4, §12.6) говорит: «ЦЕХ» не кассовая система.
* По §31.3 модуль не удаляется без согласования.
* Предложение: выключать модуль настройкой организации, по умолчанию — выключен.

**П-2. Внешние системы.** Раньше в интеграциях значились iiko и r_keeper. ТЗ 3.0 называет:
* Story House — внешний бухгалтерский контур, из него импортируются ТТК;
* двустороннюю интеграцию с r_keeper — исключение (§2.4).

Предложение:
* загрузку продаж оставить файлом;
* «r_keeper — обмен по API» снять из планов;
* добавить «Story House — импорт ТТК».

**П-3. Метод списания партий.** FEFO зашит в расход сырья, а §9.2 требует метод настройкой и только после аудита правил. Предложение: настройка «FEFO / FIFO / ручной выбор партии», по умолчанию FEFO. Фактически использованная партия хранится всегда.

**П-4. Списание по продаже.** §12.5 требует отделять расчётное потребление от фактического расхода. Сейчас продажа без выпуска списывает сырьё по ТТК как факт. Предложение: такое списание помечать «расчётное» и сверять с инвентаризацией.

## 5. Чего не хватает для работы

1. **Образцы двух типов Excel продаж** (§12.2). Без них нельзя сделать форматы.
2. **Образец выгрузки ТТК из Story House** (§7.5).
3. **План помещений пилотного предприятия** (PDF / PNG / DWG) для 2D-плана (§15.2).
4. **Инструкции дезсредств, которые реально используются.** Концентрации и экспозиции берутся только из них (§16.1).
5. **Решения по П-1 – П-4.**
