# ЦЕХ в Yandex Cloud: пошаговая инструкция

Итог: система работает по адресу `https://ваш-домен`. Данные хранятся в России (152-ФЗ). Каждую ночь делается резервная копия с проверкой восстановления, и она выгружается в хранилище Yandex Cloud.

Займёт около часа. Понадобятся: платёжный аккаунт Yandex Cloud на организацию или ИП, телефон или компьютер, по желанию — свой домен.

> Названия кнопок в консоли Yandex Cloud могут немного отличаться — интерфейс обновляется. Смысл шагов остаётся тем же.

## 1. Аккаунт

1. Откройте **console.yandex.cloud** и войдите с Яндекс ID.
2. Создайте **платёжный аккаунт** на организацию или ИП. При этом принимается оферта Yandex Cloud. Сохраните её: она понадобится юристу как договор с субподрядчиком.
3. Консоль создаст облако и каталог `default`. Всё ниже делается в нём.

## 2. Сервер (виртуальная машина)

**Compute Cloud → Виртуальные машины → Создать ВМ**:

| Поле | Значение |
|---|---|
| Образ | **Ubuntu 24.04 LTS** |
| Зона доступности | `ru-central1-a` (или `b`, `d`) |
| Диск | SSD, **30 ГБ** |
| vCPU / RAM | **2 vCPU, 4 ГБ**, гарантированная доля vCPU 100 % |
| Публичный адрес | Автоматически |
| Доступ | логин, например `ceh`, и **SSH-ключ** (см. ниже) |

**Какой размер выбрать.** Цены меняются — считайте в калькуляторе Yandex Cloud; здесь только размеры.

| Сценарий | vCPU / RAM | Диск | Комментарий |
|---|---|---|---|
| Проба, демо, один цех до 10 человек | 2 vCPU / 4 ГБ | SSD 30 ГБ | **Рекомендуемый старт.** Доля vCPU 100 %: при 20–50 % система заметно тормозит при сборке и обновлении. |
| Несколько площадок, 10–50 человек, много фото документов | 4 vCPU / 8 ГБ | SSD 60 ГБ | Размер меняется в консоли без переустановки: остановить ВМ → изменить → запустить. |
| Сеть заведений, 50+ человек | 4–8 vCPU / 16 ГБ | SSD 100 ГБ+ | Базу стоит вынести в Managed Service for PostgreSQL (`DATABASE_URL` в `.env`), файлы — в Object Storage. |

Не берите «прерываемую» ВМ: её останавливают раз в сутки. Распознавание и AI-помощник работают через облачные сервисы Yandex, поэтому видеокарта и большой сервер под них не нужны.

Внутри машины всё работает в Docker (`platform/docker-compose.yml`): база PostgreSQL, приложение, отправка почты, Telegram-бот и веб-сервер Caddy с автоматическим HTTPS.

**SSH-ключ.** На компьютере выполните в терминале `ssh-keygen -t ed25519` и вставьте в поле содержимое файла `~/.ssh/id_ed25519.pub`. С телефона подойдёт приложение Termius: оно создаёт ключ само (Keychain → Generate key).

После создания машины:

* **Сделайте адрес постоянным:** VPC → IP-адреса → у адреса машины «Сделать статическим». Иначе после перезагрузки адрес может смениться.
* **Откройте порты:** VPC → Группы безопасности. Для группы машины добавьте входящие правила:
  * TCP **443** и **80** — с любых адресов;
  * TCP **22** — лучше только с вашего IP.
* **Снимки диска по расписанию** (дополнительный уровень защиты): Compute Cloud → Снимки дисков → Расписания → ежедневно, хранить 7 штук.

## 3. Домен

* **Есть домен:** у регистратора или в Cloud DNS создайте A-запись, например `ceh.вашкафе.ru`, на статический IP машины. Кириллический домен указывайте при установке в виде punycode (`xn--…`); перевести можно на любом сайте «punycode converter».
* **Домена нет:** подойдёт `IP.sslip.io`, например `51.250.10.20.sslip.io`. Это бесплатно и работает сразу, а для пилота лучше свой домен.

## 4. Хранилище для резервных копий (Object Storage)

1. **Object Storage → Создать бакет:** имя, например `ceh-backups-вашкафе`; доступ на чтение — **ограниченный**; класс — стандартное хранилище.
2. В бакете: **Жизненный цикл → Добавить правило** — удалять объекты старше **30 дней**.
3. **Identity and Access Management → Сервисные аккаунты → Создать:** имя `ceh-backup`, роль **`storage.editor`**.
4. Откройте этот аккаунт → **Создать новый ключ → Статический ключ доступа**. Сохраните **идентификатор** (начинается с `YCAJ…`) и **секретный ключ**. Секрет показывается один раз.

## 5. Почта для писем системы

Рекомендуется **Яндекс 360 для бизнеса** на вашем домене:

1. Создайте ящик, например `ceh@вашкафе.ru`.
2. Войдите в него → **Управление аккаунтом → Безопасность → Пароли приложений → Почта** → создайте пароль.
3. При установке укажите строку:
   `smtps://ceh%40вашкафе.ru:ПАРОЛЬ_ПРИЛОЖЕНИЯ@smtp.yandex.ru:465`
   Знак `@` в имени ящика пишется как `%40`.

Почту можно настроить и позже. Пока её нет, письма системы видны в ящике стенда `https://ваш-домен/mail/` под паролем, который покажет установщик. Для первого входа этого достаточно.

## 6. Установка одной командой

Подключитесь к серверу: `ssh ceh@IP-адрес` (или через Termius). Затем выполните по очереди:

```bash
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/tceh56-boop/Brave-haccp.git /opt/ceh
cd /opt/ceh && sudo git checkout claude/dreamy-cerf-neie29
sudo bash platform/deploy/yandex-install.sh
```

> Если репозиторий закрыт (private, так и должно быть), `git clone` спросит логин и пароль. Логин — ваш логин GitHub. Пароль — **токен**: GitHub → Settings → Developer settings → Fine-grained tokens → доступ только к этому репозиторию, право *Contents: Read-only*.

Установщик:
1. ставит Docker;
2. задаёт вопросы: домен, почта (можно пропустить), бакет и ключи (можно пропустить), нужна ли демо-организация;
3. собирает и запускает систему с HTTPS — первый раз 3–7 минут;
4. делает первую резервную копию с проверкой и включает ежедневную в 03:15.

Пароли базы и почтового ящика стенда установщик генерирует сам. Они хранятся в `/opt/ceh/platform/.env` с доступом только для root.

## 7. Первый вход

1. Откройте `https://ваш-домен` → **Регистрация** → подтвердите email: письмо придёт в ваш ящик или в ящик стенда `/mail/`.
2. Создайте предприятие — вы станете владельцем.
3. Пригласите сотрудников: **☰ → Управление → Приглашения**.
4. Откройте **☰ → Готовность к пилоту**. Пункты «Резервная копия», «Письма доходят», «Изоляция организаций» должны быть зелёными. Предупреждение «сервер подключается суперпользователем базы» на этом этапе ожидаемо.

## 8. Распознавание документов (необязательно, платно)

Фото или PDF накладной ТОРГ-12 и УПД, QR-код кассового чека, банкетный бланк превращаются в черновик, который проверяет человек. Используются **Yandex Vision** (OCR) и **YandexGPT**; оплата — по страницам и токенам, по тарифам Yandex Cloud.

1. **Identity and Access Management → Сервисные аккаунты → Создать:** имя `ceh-recognition`, роли **`ai.vision.user`** и **`ai.languageModels.user`** на каталог.
2. Откройте аккаунт → **Создать новый ключ → API-ключ**. Области действия — `yc.ai.vision.execute` и `yc.ai.languageModels.execute`. Сохраните ключ: он показывается один раз.
3. Идентификатор каталога — на странице каталога (начинается с `b1g…`).
4. На сервере: `sudo nano /opt/ceh/platform/.env` → заполните `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` → `cd /opt/ceh/platform && sudo docker compose --profile https up -d`.
5. В системе: **☰ → Распознавание документов** — «настроено на сервере»; включите распознавание, выберите документы и **месячный лимит страниц**. Кнопка «Проверить подключение» делает один короткий платный запрос.

Ключи хранятся только в `.env` на сервере — в базе и на экранах их нет. Когда лимит месяца исчерпан, документы вносятся вручную.

## 9. AI-помощник «ЦЕХ ИИ» на YandexGPT (необязательно, платно)

Помощник отвечает на вопросы по требованиям со ссылкой на пункт нормативной базы системы, объясняет отклонения и предлагает черновики корректирующих действий. Он ничего не утверждает и не записывает в журналы: решение остаётся за человеком. Запросы идут в YandexGPT — данные не покидают Россию.

1. Нужен тот же сервисный аккаунт и ключ, что в разделе 8 (роль `ai.languageModels.user`).
2. В `.env`: `AI_PROVIDER=yandex`. При необходимости — `YANDEX_AI_MODEL` (по умолчанию `yandexgpt/latest`) и `AI_DAILY_LIMIT` — сколько вопросов в сутки разрешено организации (по умолчанию 300).
3. `cd /opt/ceh/platform && sudo docker compose --profile https up -d`.

Выключить: `AI_PROVIDER=off`. Без ключей помощник выключен, остальная система работает как прежде.

Тот же `AI_PROVIDER=yandex` включает и **ЦЕХ AI-агента** (экран «ЦЕХ AI»): он сам смотрит в системе проблемы на сегодня, партии, отклонения, задачи и CAPA и отвечает по ним. Агенту нужен вызов функций, поэтому он обращается к OpenAI-совместимому API AI Studio (`https://ai.api.cloud.yandex.net/v1/chat/completions`, адрес меняется настройкой `YANDEX_CHAT_URL`) с тем же ключом и каталогом. Если выбранная модель не умеет вызывать функции, попробуйте `YANDEX_AI_MODEL=yandexgpt/rc`.

## 10. Telegram-бот «ЦЕХ ИИ» (необязательно)

Бот присылает сотруднику уведомления системы (по его роли и площадке), показывает сводку смены и открытые проблемы, принимает вопросы к помощнику.

1. В Telegram откройте **@BotFather** → `/newbot` → задайте название (например «ЦЕХ ИИ») и имя, оканчивающееся на `bot`. BotFather выдаст **токен**.
2. В `.env`: `TELEGRAM_BOT_TOKEN=токен`, `TELEGRAM_BOT_USERNAME=имя_бота` (без `@`). Затем `sudo docker compose --profile https up -d`.
3. Каждый сотрудник привязывает бота сам: в системе **Смена → «Telegram-бот» → «Получить код»**, затем открывает ссылку или отправляет боту `/start КОД`. Код действует 15 минут и один раз.

Команды бота: `/smena` — что сделать в смену, `/problems` — открытые проблемы, `/stop` — отвязать, `/help`. Любой другой текст — вопрос помощнику (если он включён, раздел 9).

Что важно знать:

* Бот работает только в личных чатах, отвечает только привязанным сотрудникам и только в пределах прав их роли. У уволенного или заблокированного сотрудника доступ пропадает сразу.
* Бот сам опрашивает Telegram, входящие порты открывать не нужно. Серверу нужен исходящий доступ к `api.telegram.org`; если он недоступен, укажите в `TELEGRAM_API_URL` адрес своего прокси Bot API.
* **Сообщения проходят через серверы Telegram за пределами России.** В бота уходят тексты уведомлений и ответы на команды; персональные данные сотрудников (медкнижки, паспортные данные) в бота не передаются. Решение о подключении принимает владелец; согласуйте его с ответственным за персональные данные.
* Журнал бота: `sudo docker compose logs bot --tail 100`.

## 11. Если не Yandex Cloud: российские аналоги

Система — это обычный Docker Compose, поэтому сервер можно взять у любого российского провайдера с Ubuntu 24.04 и теми же размерами (раздел 2): **VK Cloud, Selectel, Cloud.ru, Timeweb Cloud**. Установка та же (раздел 6); резервные копии выгружаются в любое S3-совместимое хранилище — у всех перечисленных оно есть (`S3_ENDPOINT`, `S3_BUCKET` в `.env`).

Чего при этом **нет в готовом виде**:

* Распознавание документов и AI-помощник в коде подключены только к **Yandex Vision и YandexGPT**. Ими можно пользоваться и с сервера другого провайдера — нужен лишь аккаунт Yandex Cloud и ключ (разделы 8–9). Подключение другой модели (например, GigaChat) потребует доработки — отдельного адаптера.
* Мессенджер: готов только Telegram-бот. Бот для другого мессенджера — отдельная доработка; уведомления внутри системы работают без него.

Рекомендация: начинать с Yandex Cloud — сервер, хранилище, распознавание и помощник оплачиваются одним счётом и одним договором.

## Обслуживание

| Задача | Команда на сервере |
|---|---|
| Обновить систему до новой версии | `cd /opt/ceh/platform && sudo bash deploy/update.sh` |
| Резервная копия вручную | `cd /opt/ceh/platform && sudo bash deploy/backup.sh` |
| Журнал копий | `sudo tail -50 /var/log/ceh-backup.log` |
| Журнал Telegram-бота | `cd /opt/ceh/platform && sudo docker compose logs bot --tail 100` |
| Журнал системы | `cd /opt/ceh/platform && sudo docker compose logs app --tail 100` |
| Изменить настройки (почта, ключи) | `sudo nano /opt/ceh/platform/.env`, затем `sudo docker compose --profile https up -d` |

**Восстановление из копии** — по разделу 3 документа `docs/ПИЛОТ_ЭТАП_8.md`. Копии лежат в бакете, в папке `ceh-backups/`, и на сервере в томе `backups`.
