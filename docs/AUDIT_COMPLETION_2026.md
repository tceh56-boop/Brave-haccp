| **ГОТОВО** | Есть все шесть элементов: пользовательский сценарий в интерфейсе, серверная проверка прав, запись в аудит, обработка ошибок, автотест, инструкция пользователя |

## 6. Архитектурные решения (фиксируются до разработки)

1. **Стек не меняется.** Next.js 16, PostgreSQL 16, RLS, `inOrg`, `once()`, аудит. Новые сущности — только миграциями `049+`.
2. **Факт и расчёт.** Новая таблица `consumption_estimates` — расчётное потребление: продажа × ТТК, норма выпуска. В движения склада `stock_movements` пишется только факт: приёмка, фактический расход, выпуск, списание, инвентаризация, перемещение.
3. **Классы потерь.** У движения появляется поле `loss_class`: `technological`, `sanitary`, `emergency`, `commercial`, `unexplained`. Классы сопоставляются с причинами списания.
4. **Экономика партии.** Цена единицы партии — существующее поле `lots.unit_price` (повторно не заводится). К нему добавляется `cost_basis` (jsonb: формула, входные движения, цены, метод, версия). Стоимость фиксируется при создании партии и не переписывается; пересчёт — новая запись.
5. **Санитарное состояние оборудования.** Отдельная машина состояний `equipment_sanitary_state` с журналом переходов. Время экспозиции — только серверное.
6. **Партии дезсредств.** Используются общие таблицы `products`, `lots`, `stock_movements` с видом товара «химия» — без параллельного склада (ТЗ 3.0 §3.1).
7. **2D-геометрия.** Хранится в реальных единицах (мм) в таблицах `floor_plans`, `plan_objects`, `plan_routes`. Отображение 2D и 3D — отдельные модули, читают одни и те же данные.
8. **Чек-листы.** Таблицы `checklist_templates`, `checklist_items` с версией документа-источника и `checklist_runs`. Пропуск создаёт задачу; норма не подставляется вместо факта.
9. **Внешний врач.** Таблица `expert_access_grants`: срок действия, площадки, только чтение и замечания. Просмотры пишутся в аудит.

## 8. Критерии приёмки этапа 1

1. Завершение производства без фактических партий отклоняется. Фактический расход хранится по каждой партии. Отклонение от нормы ТТК показано отдельно и не скрыто.
2. Повтор завершения с тем же ключом операции не создаёт вторых движений.
3. Продажа создаёт расчётное потребление. Остаток склада она меняет только по утверждённой методике сверки, и такая запись помечена как «расчётное».
4. У каждого списания есть класс потерь. Отчёт по партии сходится по формуле: начальный остаток + приход − расход − списания ± перемещения = остаток.
5. Себестоимость партии выпуска раскрывается до партий сырья, количеств и цен. Изменение закупочной цены её не меняет.
6. Отзыв показывает открытые производственные задания на заблокированное сырьё.
7. На каждый пункт — автотест и раздел инструкции.
