# MonChef License API

Отдельный закрытый Apps Script-проект владельца MonChef. Выдаёт клиентским установкам MonChef
лицензированную нормативную базу по `licenseId`, проверяет лицензию и ключ установки, ведёт журнал обращений
и уведомляет владельца о подозрительных событиях.

**Что API защищает:** управляемую нормативную базу, её обновления, учёт лицензий и установок, журнал обращений.
**Что API не защищает:** исходный код MonChef у клиента (см. «Ограничения»).

│   ├── INSTALLATIONS   — установки по лицензиям

│   └── ADMIN_LOG       — административный журнал и уведомления
├── MONCHEF_NORMATIVE_BASE (закрытая)  — папка (ID: MC_NORMATIVE_ROOT_FOLDER_ID)
│   ├── official/       — официальные нормативные тексты (рекомендуемая структура)
│   ├── guides/         — пояснения MonChef
│   ├── templates/      — шаблоны
│   ├── mappings/       — таблицы соответствий
│   ├── methodology/    — методические документы
│   └── internal/       — внутренние материалы (не выдаются никогда)
└── Проект Apps Script «MonChef License API»

Google Диск КЛИЕНТА (установка MonChef)
├── книга MON CHEF → лист «Лицензия_Нормативная_база» (реестр загруженных документов)

Подпапки внутри закрытой папки — рекомендация; API проверяет только, что файл лежит где-то внутри неё.

## 3. Схема таблиц

### LICENSES

| Столбец | Описание |
|---|---|
| `licenseId` | `MC-2026-0001` |
| `clientId` | `CLIENT-0001` — должен совпасть с запросом |
| `customerName`, `customerEmail` | Для владельца; клиенту и в журналы не выдаются |
| `clientTokenHash` | HMAC-SHA-256 токена (hex). Сам токен не хранится |
| `status` | `ACTIVE`, `SUSPENDED`, `EXPIRED`, `REVOKED`, `TEST` |
| `validFrom`, `validUntil` | `yyyy-MM-dd`, включительно, по часовому поясу проекта |
| `allowedModules` | `NORM_BASE,TEMPLATES` или `*` |
| `allowedDocuments` | `NORM-0001,NORM-0002` или `*` (все документы разрешённых модулей). Пусто — ничего |
| `maxInstallations` | Лимит одновременно активных установок (по умолчанию 1) |
| `currentInstallations` | Число активных установок (ведёт API) |
| `lastSeenAt`, `lastSeenInstallationId`, `requestCount` | Обновляются не чаще раза в 10 минут |
| `notes`, `createdAt`, `updatedAt` | Служебные |
| `plan` | **Добавлено к ТЗ.** Тариф (`STANDARD`, `PRO`, `TEST`…) — сверяется с `DOCUMENTS.allowedPlans` |

| Статус | Доступ |
|---|---|
| `ACTIVE` | разрешён в пределах модулей, документов и тарифа |
| `TEST` | только модуль `TEST` и документы с `TEST` в `allowedPlans` |
| `SUSPENDED`, `REVOKED` | запрещён → `LICENSE_INACTIVE` |
| `EXPIRED` (или дата позже `validUntil`) | запрещён → `LICENSE_EXPIRED` |

### DOCUMENTS

`documentId`, `fileId`, `title`, `description`, `module`, `version`, `status` (`DRAFT`, `ACTIVE`, `ARCHIVED`, `BLOCKED`),
`mimeType`, `sha256`, `sizeBytes`, `allowedPlans` (`*` или список тарифов; пусто — никому), `publishedAt`, `updatedAt`,
`isOfficialSource`, `sourceUrl`, **`category`** (добавлено к ТЗ):

| category | Правовой статус |
|---|---|
| `OFFICIAL` | Официальный нормативный текст. `isOfficialSource = TRUE`, `sourceUrl` — официальный источник (обязателен) |
| `MONCHEF_GUIDE` | Собственные пояснения MonChef |
| `TEMPLATE` | Шаблоны форм и журналов |
| `MAPPING` | Таблицы соответствий |
| `METHODOLOGY` | Методические документы |
| `INTERNAL` | Внутренние материалы — не публикуются и не выдаются |

Клиент получает `category`, `isOfficialSource` и `sourceUrl` вместе с документом, чтобы официальные тексты
и материалы MonChef были разделены и на стороне клиента.

### INSTALLATIONS (добавлено к ТЗ)

`licenseId`, `installationId`, `status` (`ACTIVE`, `BLOCKED`, `RELEASED`), `firstSeenAt`, `lastSeenAt`, `appVersion`, `notes`.
Новая установка регистрируется автоматически, пока не исчерпан `maxInstallations`. Слот освобождает только владелец.

### REQUESTS

`requestId`, `licenseId`, `clientId`, `installationId`, `action`, `payloadHash`, `status`, `responseJson`, `createdAt`, `finishedAt`.
`requestId` уникален в пределах лицензии. `responseJson` хранится без содержимого документа.

### API_AUDIT

`timestamp`, `requestId`, `licenseId`, `clientId`, `installationId`, `action`, `documentId`, `module`, `result` (`OK`, `ERROR`, `REPLAY`),
`errorCode` (внутренний точный код, например `INVALID_TOKEN`), `appVersion`, `apiVersion`, `durationMs`.
Не пишутся: токен, хеш токена, содержимое документов, IP-адрес, email, пароли.

### ADMIN_LOG (добавлено к ТЗ)

`timestamp`, `actor`, `action`, `licenseId`, `documentId`, `details`. Регистрация и отзыв лицензий, замена токена,
установки, публикация документов, проверки целостности, уведомления (`NOTIFY_*`).

| Scope | Зачем |
|---|---|
| `spreadsheets` | Таблица реестра |
| `drive` | Чтение файлов закрытой папки; создание папки и тестового файла при настройке. Права доступа к файлам API не меняет |
| `script.scriptapp` | Ежедневный триггер проверки целостности |

## 5. Модель лицензирования

* **Лицензия** (`licenseId`) выдаётся клиенту (`clientId`) на срок, с набором модулей, документов, тарифом и лимитом установок.
* **Установка** (`installationId`) — конкретная копия MonChef (создаётся автоматически при первом запуске коннектора).
  Каждая установка занимает слот лицензии.
* **Токен установки** — длинный случайный секрет (`mct_…`, 512 бит из двух SHA-256 от случайных UUID). В реестре хранится
  только `HMAC-SHA-256(токен, MC_TOKEN_PEPPER)`. Токен показывается владельцу один раз при выдаче или замене.
* **Документ** выдаётся, если: опубликован (`ACTIVE`), не `INTERNAL`, модуль разрешён, документ разрешён
  (`allowedDocuments`), тариф лицензии входит в `allowedPlans`, размер ≤ `MC_MAX_DOCUMENT_BYTES`, SHA-256 файла
  совпадает с реестром. Всё, что не разрешено явно, запрещено.
* **Версия библиотеки** (`MC_LIBRARY_VERSION`) меняется автоматически при публикации, снятии и обновлении хеша документа.

## 6. Операции API

Все запросы — `POST` с JSON на адрес веб-приложения (`…/exec`). Запрос ≤ 100 КБ, строки ≤ 500 символов,
только поля из списка ниже (любое другое поле, в том числе `fileId`, — `INVALID_REQUEST`).

```json
{
  "requestId": "CLIENT-0001-20261119-000001",
  "licenseId": "MC-2026-0001",
  "clientId": "CLIENT-0001",
  "installationId": "INSTALL-8F2A-…",
  "clientToken": "mct_…",
  "action": "LIST_DOCUMENTS",
  "appVersion": "1.0.0",
  "module": "NORM_BASE"
}
```

| action | Доп. поле | Ответ `result` |
|---|---|---|
| `CHECK_LICENSE` | — | `licenseId`, `clientId`, `status`, `validFrom`, `validUntil`, `apiVersion`, `libraryVersion`, `offlineGraceDays` |
| `GET_LIBRARY_VERSION` | — | `libraryVersion`, `publishedAt`, `modules` (модули, где лицензии доступен хотя бы один документ) |
| `LIST_DOCUMENTS` | `module` | `module`, `libraryVersion`, `documents[]`: `documentId`, `title`, `description`, `module`, `version`, `category`, `isOfficialSource`, `sourceUrl`, `sha256`, `mimeType`, `sizeBytes`, `updatedAt` |
| `GET_DOCUMENT` | `documentId` | метаданные как в списке + `fileName` (`NORM-0001.pdf`) + `contentBase64` |

`offlineGraceDays` добавлен к ответу CHECK_LICENSE, чтобы клиент применял срок из договора, а не только свой.

Успех: `{"ok":true,"requestId":"…","result":{…},"serverTime":"…"}`.
Ошибка: `{"ok":false,"requestId":"…","error":"LICENSE_EXPIRED","message":"Срок лицензии истёк","retryable":false,"serverTime":"…"}`.
Повтор `requestId` возвращает сохранённый ответ с `"replayed": true`.

**Большие документы.** До `MC_MAX_DOCUMENT_BYTES` (5 МБ) файл передаётся в `contentBase64`. Больше — `DOCUMENT_TOO_LARGE`:
Base64 для больших файлов не используется, публичный доступ к файлу не открывается. Такие материалы делятся на части
или передаются клиенту подготовленной копией по договору.

## 7. Коды ошибок

| Код | Сообщение клиенту | retryable | Когда |
|---|---|---|---|
| `INVALID_REQUEST` | Некорректный запрос | нет | не JSON, лишнее поле (`fileId`, `status`…), нет обязательного поля, неверный формат, строка > 500 |
| `REQUEST_TOO_LARGE` | Запрос больше 100 КБ | нет | |
| `METHOD_NOT_ALLOWED` | Только POST | нет | GET |
| `UNKNOWN_ACTION` | Неизвестная операция | нет | |
| `AUTH_FAILED` | Лицензия не найдена или данные доступа неверны | нет | наружу вместо трёх кодов ниже при `MC_STRICT_AUTH_ERRORS=true` (по умолчанию) |
| `LICENSE_NOT_FOUND` | Лицензия не найдена | нет | в API_AUDIT всегда; наружу — только в нестрогом режиме |
| `CLIENT_MISMATCH` | Лицензия выдана другому клиенту | нет | то же |
| `INVALID_TOKEN` | Неверный ключ доступа установки | нет | то же |
| `LICENSE_INACTIVE` | Лицензия приостановлена, отозвана или ещё не действует | нет | `SUSPENDED`, `REVOKED`, до `validFrom` |
| `LICENSE_EXPIRED` | Срок лицензии истёк | нет | `EXPIRED` или после `validUntil` |
| `INSTALLATION_NOT_ALLOWED` | Установка не разрешена | нет | лимит установок, установка `BLOCKED`/`RELEASED` |
| `MODULE_NOT_ALLOWED` | Модуль не входит в лицензию | нет | |
| `DOCUMENT_NOT_ALLOWED` | Документ не входит в лицензию | нет | не в `allowedDocuments` или не тот тариф |
| `DOCUMENT_NOT_FOUND` | Документ не найден или снят с публикации | нет | нет, `DRAFT`/`ARCHIVED`/`BLOCKED`/`INTERNAL`, файл в корзине |
| `DOCUMENT_TOO_LARGE` | Слишком большой для выдачи через API | нет | |
| `DOCUMENT_INTEGRITY_FAILED` | Не пройдена проверка целостности | да | SHA-256 файла ≠ реестру; документ переведён в `BLOCKED` |
| `RATE_LIMIT_EXCEEDED` | Слишком много запросов | да | |
| `REQUEST_ID_PAYLOAD_MISMATCH` | requestId уже использован для другого запроса | нет | |
| `PROCESSING` | Запрос ещё выполняется | да | параллельный запрос с тем же requestId |
| `BUSY` | Сервис занят | да | не взята блокировка |
| `SERVICE_UNAVAILABLE` | Сервис временно недоступен | да | таблица или Drive недоступны, не настроен реестр |
| `INTERNAL_ERROR` | Внутренняя ошибка | да | прочие исключения (текст — только в журнале выполнения владельца) |

Статус и сроки лицензии сообщаются только после проверки токена: посторонний не узнает, что лицензия существует,
отозвана или истекла. Для неизвестной и существующей лицензии с неверным токеном ответ одинаковый.

## 9. Установка License API

1. Под аккаунтом владельца MonChef: script.google.com → «Новый проект» → название **MonChef License API**.
2. Создайте файлы и вставьте содержимое: `Config.gs`, `RegistryStore.gs`, `LicenseService.gs`, `DocumentService.gs`,
   `AuditService.gs`, `SecurityService.gs`, `NotificationService.gs`, `ApiRouter.gs`, `Setup.gs`, `Tests.gs`.
   «Настройки проекта» → «Показывать файл манифеста» → замените `appsscript.json`.
   (Или `clasp push` из папки `monchef/license-api`, исключив `tools/` и `*.md` через `.claspignore`.)
3. Выполните `MC_runAllTests` — в журнале должно быть «Итого: N из N». Тесты не трогают реальные данные.
4. Выполните `MC_setupLicenseRegistry` и подтвердите доступ. Будут созданы таблица, листы, закрытая папка,
   `MC_TOKEN_PEPPER`, `MC_ADMIN_EMAIL`, ежедневный триггер проверки целостности (03:00).
5. «Развернуть» → «Новое развертывание» → «Веб-приложение»: **Выполнять как: Я (владелец)**,
   **У кого есть доступ: Все**. Скопируйте адрес `…/exec`.
   «Все» нужно, чтобы клиентский сервер мог обращаться без входа в Google; доступ ограничивают licenseId и токен.
   Код проекта, таблица и папка при этом клиентам недоступны.
6. Проверьте безопасность (раздел 16).

## 10. Регистрация лицензии

1. В `Setup.gs` откройте `MC_ADMIN_registerLicenseExample`, укажите `clientId`, срок, модули, документы, тариф, лимит установок.
2. Запустите. В журнале выполнения — `licenseId` и **токен (один раз)**.
3. Передайте токен установщику клиента лично или через менеджер паролей/защищённый канал — **не обычной почтой**.
4. В клиентском MonChef технический доступ задаёт подключение одним из способов:
   * Script Properties клиентского проекта: `MC_LICENSE_API_URL`, `MC_LICENSE_ID`, `MC_CLIENT_ID`, `MC_CLIENT_TOKEN`, `MC_APP_VERSION`;
   * или вызов `mcLicenseConfigure('{"url":"…/exec","licenseId":"MC-2026-0001","clientId":"CLIENT-0001","clientToken":"mct_…","appVersion":"1.0.0"}')`
     из редактора — функция сохранит настройки, поставит ежедневную проверку (04:00) и сразу проверит лицензию.
5. Директор видит статус: «Настройки» → вкладка «Лицензия».

## 11. Регистрация и публикация документов

1. Положите файл (PDF, DOCX, XLSX, TXT…; не Google Документ) в закрытую папку `MONCHEF_NORMATIVE_BASE`.
2. `MC_ADMIN_registerDocumentExample` → `documentId`, `fileId`, модуль, категория, тарифы. Документ появится как `DRAFT`, хеш посчитается.
3. `MC_publishDocument('NORM-0001')` — хеш сверяется заново, статус `ACTIVE`, версия библиотеки обновится.
4. Замена файла новой редакцией: замените содержимое файла → `MC_refreshDocumentHash('NORM-0001', '2026.12')`.
5. Снять с публикации: `MC_unpublishDocument('NORM-0001', 'причина')` — у клиентов документ останется загруженным с пометкой «Снят с публикации».

## 12. Тестовая лицензия и тестовый документ

`MC_createTestFixtures()` создаёт в закрытой папке `MonChef_test_document.txt`, регистрирует и публикует документ
`TEST-0001` (модуль `TEST`, тариф `TEST`) и лицензию со статусом `TEST` на 30 дней (`clientId = CLIENT-TEST`,
1 установка). Токен — в журнале выполнения. Проверка вручную:

```bash
curl -sL -H 'Content-Type: application/json' -d '{"requestId":"CLIENT-TEST-0000000001","licenseId":"MC-2026-0001","clientId":"CLIENT-TEST","installationId":"INSTALL-MANUAL-0001","clientToken":"mct_…","action":"LIST_DOCUMENTS","module":"TEST","appVersion":"1.0.0"}' 'https://script.google.com/macros/s/…/exec'
```

После проверки отзовите тестовую лицензию: `MC_revokeLicense('MC-2026-0001', 'тест завершён')`.

## 13. Отзыв лицензии, приостановка, продление

* `MC_revokeLicense(licenseId, причина)` — окончательно; `MC_suspendLicense(licenseId, причина)` — временно;
  `MC_reactivateLicense(licenseId, причина)` — вернуть `ACTIVE`; `MC_extendLicense(licenseId, 'yyyy-MM-dd', причина)` — продление.
* Действует сразу: кэш лицензии сбрасывается. Если статус правили вручную в таблице — выполните `MC_clearCaches()`
  (иначе изменение подхватится в течение 5 минут).
* У клиента: режим «Лицензия не действует», новые документы не загружаются. **Данные кухни, журналы и уже
  загруженные документы не удаляются и не блокируются.**
* Установки: `MC_releaseInstallation(licenseId, installationId)` — освободить слот (клиент переустановил MonChef);
  `MC_blockInstallation(licenseId, installationId)` — заблокировать копию.

## 14. Замена токена

1. `MC_rotateClientToken(licenseId, 'причина')` — новый токен в журнале выполнения (один раз); старый перестаёт действовать сразу.
   Замена записывается в ADMIN_LOG (`TOKEN_ROTATED`).
2. Передайте новый токен установщику защищённым каналом; он обновляет `MC_CLIENT_TOKEN` (или `mcLicenseConfigure`).
3. До обновления у клиента режим «Лицензия не действует» (`AUTH_FAILED`); работа кухни не прерывается.

Когда менять: при утечке, при смене подрядчика-установщика, по сигналу `BAD_TOKENS`, плановая замена — раз в год.

## 15. Offline grace period

* После каждой успешной проверки клиент запоминает время (`lastOkAt`) и льготный срок (`offlineGraceDays` из ответа API,
  по умолчанию 7 дней; можно переопределить `MC_OFFLINE_GRACE_DAYS` у клиента).
* API недоступен (нет сети, HTTP-ошибка, не JSON, `SERVICE_UNAVAILABLE`):
  * до истечения срока — режим **GRACE** («Нет связи с сервисом — льготный период до …»);
  * после — **LIMITED**: работает последняя загруженная версия базы, обновления не загружаются, директору показано предупреждение.
* В обоих режимах ничего не блокируется и не удаляется: записи, журналы, документы кухни, загруженная база.
* Повторы: одна попытка + один повтор с тем же `requestId`, затем паузы 5 мин → 15 мин → 1 ч → 6 ч. Бесконечных повторов нет.
  Плановая проверка — раз в сутки (триггер `mcLicenseDailyCheck`, 04:00).
* Связь вернулась — следующая проверка переводит в **OK** и догружает обновления.
* Значение льготного срока **указывается в договоре** (см. раздел 18).

## 16. Безопасность — чек-лист

- [ ] Проект License API: «Поделиться» — только владелец. Не добавлять редакторов.
- [ ] Таблица MONCHEF_LICENSE_REGISTRY и папка MONCHEF_NORMATIVE_BASE: доступ только у владельца (проверить «Настройки доступа»).
- [ ] Веб-приложение: «Выполнять как: Я», доступ «Все». API никогда не меняет права файлов (в коде нет `setSharing`/`addViewer`).
- [ ] Клиент передаёт только `documentId`; `fileId`, ID папки, ссылки Drive в ответах нет (покрыто тестами).
- [ ] Права доступа из запроса не принимаются: поля `status`, `allowedModules` и любые лишние — `INVALID_REQUEST`.
- [ ] Клиент не может изменить статус лицензии: операций записи в API нет; административные функции — только владелец в редакторе.
- [ ] Перечислить `licenseId` нельзя: строгий режим ошибок, одинаковый ответ для несуществующей лицензии и неверного токена.
- [ ] Токены в ответах, API_AUDIT, REQUESTS и письмах отсутствуют (покрыто тестами). В реестре — только HMAC-хеш.
- [ ] `MC_TOKEN_PEPPER` есть в резервной копии свойств и нигде больше.
- [ ] Значения из запросов записываются в таблицу с защитой от формул (`'=` и т. п.).

## 17. Угрозы и ограничения

| Угроза | Мера | Остаточный риск |
|---|---|---|
| Подбор токена | 512 бит случайности, HMAC-хеш, уведомление `BAD_TOKENS` | практически нет |
| Перечисление лицензий | `AUTH_FAILED` для всех трёх случаев, одинаковое время проверки | — |
| Утечка таблицы реестра | токены не восстановить без `MC_TOKEN_PEPPER` | данные клиентов (имя, email) — защищать доступом к таблице |
| Копирование установки | лимит установок, `MULTI_INSTALL`, блокировка установки | копия, не обращающаяся к API, работает с уже загруженной базой |
| Извлечение токена клиентом | — | **клиент с доступом к своему коду или Script Properties может извлечь свой токен**; токен идентифицирует установку, но не защищает от владельца исходников |
| Подмена файла в папке | SHA-256 при выдаче и ежедневно, блокировка `BLOCKED`, `HASH_MISMATCH` | — |
| Подмена ответа по пути | HTTPS Google; клиент сверяет SHA-256 содержимого | — |
| Перегрузка | лимиты в минуту на лицензию и операцию, уведомление `REQUEST_SPIKE` | квоты Apps Script владельца (UrlFetch клиента, время выполнения) |

**Честные ограничения (указать в документации и договоре):**

* `licenseId` и токен **не являются абсолютной защитой** от клиента, который владеет исходным кодом своей установки MonChef.
* Клиент может изменить или удалить клиентский коннектор. Тогда он перестаёт получать обновления базы, но сохранённые копии остаются у него.
* API защищает доступ к **обновляемой** нормативной базе и фиксирует обращения; он **не защищает исходный код** MonChef.
* Журнал API сам по себе **не доказывает перепродажу**. Доказательством нарушения служит совокупность: договор, лицензия,
  повторная активация (новые `installationId`), индивидуальная маркировка выданных материалов, журнал API и переданная копия.
* Официальные нормативные тексты (`OFFICIAL`, с источником) и собственные материалы MonChef разделены по правовому статусу;
  лицензируются собственные материалы MonChef и подборка/сервис, а не официальные тексты как таковые.
* Клиент уведомлён о работе API лицензирования (текст для договора — ниже).

## 18. Текст для договора и клиентской документации

> MonChef периодически (не реже раза в сутки и при нажатии «Проверить лицензию») обращается к сервису лицензирования
> MonChef для проверки лицензии и получения обновлений нормативной базы. При обращении передаются: номер лицензии,

## 19. Резервное копирование

* **Таблица реестра:** еженедельно «Файл → Создать копию» в отдельную закрытую папку владельца (или Google Takeout).
  Копия содержит хеши токенов и email клиентов — хранить так же закрыто.
* **Script Properties API:** выгрузите значения (особенно `MC_TOKEN_PEPPER`, `MC_LICENSE_REGISTRY_SHEET_ID`,
  `MC_NORMATIVE_ROOT_FOLDER_ID`) в менеджер паролей владельца. Без `MC_TOKEN_PEPPER` все выданные токены придётся заменить.
* **Код:** репозиторий `monchef/license-api` + версии развертываний Apps Script («Управление развертываниями»).
* **Нормативная база:** копия папки `MONCHEF_NORMATIVE_BASE` (Google Drive сохраняет версии файлов 30 дней; храните исходники отдельно).
* **API_AUDIT/REQUESTS** растут: раз в квартал переносите старые строки в архивную копию таблицы (не удаляя без копии).

## 20. План внедрения без поломки существующей системы

1. Развернуть License API, прогнать `MC_runAllTests`, `MC_setupLicenseRegistry`, `MC_createTestFixtures`.
2. Проверить тестовой лицензией вручную (curl, раздел 12).
3. В клиентский MonChef добавить `MonChef_LicenseClient.gs` и изменения `zzz_MonChef_Gate.gs`, `MonChef_UI.gs`.
   Без настройки коннектор ничего не делает (`NOT_CONFIGURED`), MonChef работает как раньше.
4. Пилот: одна установка с тестовой лицензией → проверка статуса в «Настройки → Лицензия», загрузка `TEST-0001`.
5. Загрузить и опубликовать реальные документы; выдать боевые лицензии; настроить установки клиентов.
6. Неделю наблюдать API_AUDIT и ADMIN_LOG, затем подобрать пороги уведомлений.

## 21. План отката

* **Клиент:** удалить `MC_LICENSE_API_URL` (или все `MC_LICENSE_*`) из Script Properties → режим `NOT_CONFIGURED`;
  удалить триггер `mcLicenseDailyCheck`. Полный откат кода: убрать `MonChef_LicenseClient.gs` и вернуть
  `zzz_MonChef_Gate.gs`, `MonChef_UI.gs` из предыдущего коммита. Загруженные документы и лист
  «Лицензия_Нормативная_база» остаются у клиента.
* **API:** «Управление развертываниями» → выбрать предыдущую версию (адрес `…/exec` не меняется).
  Аварийно закрыть выдачу всем: архивировать развертывание (клиенты перейдут в GRACE/LIMITED, данные не пострадают).
* **Реестр:** восстановить из копии таблицы; при восстановлении старой копии выполнить `MC_clearCaches()`.
