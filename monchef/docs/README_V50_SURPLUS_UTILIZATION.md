# Mon Chef V50 — использование излишков

V50 продолжает V49. V49 делает физическую ревизию источником фактического остатка; V50 ищет безопасное применение доступного остатка до новой закупки/нового выпуска.

## Логика
`Склад_Партии → V25 производственный план → FEFO-сопоставление → рекомендация → резерв/задача → реальная операция`

V50 не создаёт второй склад и не меняет остаток при построении рекомендации.

### Источники
- `Склад_Партии` — фактические активные партии.
- `Производство_План_V25` — будущая потребность RAW_PICK, П/Ф и готовых блюд.
- V49 — исключение партий, отмеченных как карантин/заблокированные/повреждённые.
- активные V50-резервы уменьшают доступный для повторного сопоставления остаток.

### Действия
- `USE_IN_PRODUCTION_PICK` — существующий излишек сырья можно направить в отбор под производство.
- `USE_PF_IN_PRODUCTION` — существующий П/Ф может заменить часть планового выпуска.
- `FINISHED_BANQUET_REVIEW` — готовый продукт может быть рассмотрен для банкета, но автоматической выдачи нет.
- `REVIEW_SURPLUS` — излишек не имеет подходящей потребности в заданном горизонте.

## Безопасность
- Просроченные партии не сопоставляются.
- Скоро истекающие партии получают приоритет `URGENT`/`AT_RISK`.
- Система не придумывает срок годности.
- Система не продлевает срок годности.
- Рекомендация не является списанием.
- `v50ReserveRecommendation` создаёт только внутренний резерв; физический остаток не уменьшается.
- `v50ApproveRecommendation` создаёт операционную задачу; фактическое списание происходит существующими складскими/производственными операциями.

## UI
`?surplus=1&token=...`

## Следующий технический шаг
Интегрировать V50 непосредственно в V48: перед созданием задачи «довыпустить/запустить производство» сначала проверять, можно ли закрыть дефицит имеющимся излишком. Для этого потребуется точное связывание сырьевой потребности с конкретным production_id и перерасчёт TTK после подтверждённого использования.
