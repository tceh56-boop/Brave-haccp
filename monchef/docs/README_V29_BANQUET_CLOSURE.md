# Mon Chef V29 — Фактический банкет и закрытие

V29 завершает операционный контур после V28.

## Поток
`банкет -> план -> ТТК -> закупка -> склад/FEFO -> отбор -> выпуск -> готовая партия -> выдача -> фактически обслужено -> возврат/брак -> закрытие`

## Что добавлено
- `Факт_Банкет_V29` — фактическое обслуживание по блюдам.
- `Карантин_Возврат_V29` — возвраты с банкета; они не возвращаются автоматически в свободный склад.
- `Закрытие_V29` — один неизменяемый факт закрытия на банкет.
- Проверка: `обслужено + возврат + брак = фактически выдано`.
- J36 формируется по фактически обслуженному количеству, а не по плану.
- При наличии брака создаётся автоматическая запись/ожидание бракеража; решение комиссии остаётся человеческим фактом.
- FACT и Audit фиксируют закрытие.
- Себестоимость берётся из фактических выдач V28 и фиксируется при закрытии.
- Повторное закрытие блокируется.

## UI
`...?closure=1&token=...`

## Важные ограничения
1. Система не придумывает фактические количества.
2. Возвращённая готовая продукция не возвращается на свободный склад автоматически.
3. Для юридически значимой электронной подписи используется существующий механизм подписания/ЭП; обычный вход в приложение не считается квалифицированной ЭП.
4. Регламентные сроки годности не вычисляются из предположений: используются данные ТТК/партии или ввод ответственного.

## Предрелизная проверка
1. Создать тестовый банкет.
2. Выполнить V26/V27: резерв -> отбор -> выпуск.
3. Выполнить V28: выдача.
4. В V29 распределить выданное между обслужено/возврат/брак.
5. Закрыть банкет.
6. Проверить `Факт_Банкет_V29`, `Карантин_Возврат_V29`, `Закрытие_V29`, J36, J02 и Audit_Log.
7. Повторно нажать закрытие: операция должна быть отклонена.
