# MON CHEF — FINAL PROJECT PACKAGE

Финальный объединённый исходный комплект системы управления рестораном и банкетным производством.

## Что внутри

- `Code.gs` — единая серверная точка входа и объединённое ядро production-релиза.
- `Console.html` — главное окно MON CHEF: единый интерфейс, все модули — его экраны. Прежний интерфейс (`App.html`) и отдельные страницы модулей V22–V63 удалены; старые адреса открывают главное окно.
- `monchef_mark.png` / `monchef_wordmark.png` — фирменный знак и логотип.
- Все серверные `.gs` модули предыдущих функциональных блоков.
- Рабочие страницы нового интерфейса (журналы, приёмка, партия, обработка, сотрудники, документы и др.) и портал проверяющего — в оформлении главного окна.
- Документация и release/deploy материалы.
- Выпуск и пилот — экран главного окна «Выпуск и пилот» (технический доступ).
- `DEPLOY_MANIFEST_FINAL.json` — состав финальной сборки.
- `FINAL_UI_REFERENCE.png` — визуальный референс интерфейса.

## Основной операционный контур

Заказ/банкет → меню → ТТК → расчёт потребности → склад/партии → FEFO → дефицит/излишек → производство → ПФ/готовая продукция → отбор → выдача → возврат/брак → FACT → HACCP/журналы → закрытие.

## Ключевой принцип склада

`Склад_Партии` остаётся единым источником фактического остатка. Ресурсный слой использует `ProductID`, `BatchID`, операции, резервы и аудит. В пользовательском интерфейсе внутренние номера разработки Vxx не отображаются.

## Перед запуском

1. Сделать копию рабочей Google-таблицы.
2. Развернуть `Code.gs` и HTML/GS-файлы как один Apps Script project.
3. Проверить `appsscript.json` и OAuth scopes под фактическую организацию.
4. Выполнить миграцию ресурсов на копии базы.
5. Проверить ProductID-сопоставления со статусом REVIEW.
6. Провести резервное копирование и тест восстановления.
7. Прогнать полный приёмочный сценарий: банкет → ТТК → закупка/остаток → производство → выдача → HACCP → закрытие.
8. Только после этого переводить реальную кухню на новый контур.

## Важно

Архив является исходным production-кандидатом. Статический ZIP сам по себе не доказывает эксплуатационную или юридическую готовность. Перед фактическим запуском необходимы тесты на рабочей копии данных, проверка прав доступа, резервного восстановления, нормативной документации и, где требуется, юридически значимой электронной подписи.
