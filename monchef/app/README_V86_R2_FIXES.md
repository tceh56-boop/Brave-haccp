# Mon Chef V86 — исправления по повторному аудиту R2 (18.11.2026)

Основание — внешний отчёт «Повторный аудит MonChef после исправлений» от 18.11.2026 (статический аудит сборки). Каждое конкретное замечание сначала проверено по коду; подтвердились все шесть, они исправлены. Архитектурные предложения аудита (единый конвейер событий, единый экран «Моя смена», единый ответ операции, пилот приёмки) — отдельный план, в этой сборке не начинались.

## Что исправлено

| Замечание аудита | Подтвердилось в коде | Что сделано |
|---|---|---|
| **P0.1** Фритюр пишет в J38 и в лист циклов двумя отдельными действиями; повтор — риск дубля или «зависшего» цикла | да: сначала строка J38, потом цикл; повтор — отказ «уже в работе» | сначала записывается **цикл**, затем шаги (склад → строка J38), каждый выполненный шаг отмечается в цикле. Повтор с тем же ключом нажатия (или тот же сотрудник с теми же данными в течение 2 минут) возвращает **тот же цикл** (`idempotent`), второго цикла и второй строки J38 нет. Если связь оборвалась между шагами, на экране — карточка «запись не завершена» и кнопка **«Дописать начало» / «Дописать окончание»**: доводится только невыполненный шаг, масло со склада второй раз не списывается |
| **P0.2** Замена масла не связана со складской партией | да | в «Залил масло» можно выбрать **партию масла со склада** (растительное, фритюрный жир, топлёное): количество списывается с проверкой состояния партии, FEFO и остатка (как любое использование партии), цикл связан с партией в прослеживаемости; утилизированный жир — связь цикла с утилизацией |
| **P0.3** Две модели осмотра: вопросы J07 по расписанию и самоотметка V81 | да: одобрение V81 всегда дописывало новую строку J07, вопрос по расписанию оставался открытым | одна модель: **самоотметка → осмотр ответственного → одна строка J07**. Вопросы J07 по расписанию больше не создаются (их можно вернуть на экране «Здоровье на смену» — ответственный за ХАССП или директор). Если строка J07 уже заведена (до обновления или в прежнем режиме), осмотр **дописывает её** и закрывает её вопрос; ответ на вопрос журнала виден на экране осмотра, повторно не записывается. Не отметившихся видно списком — ответственный может осмотреть лично |
| **P1.1** Инструктаж может задвоиться при повторной отправке | да | та же запись (сотрудник, вид, тема, дата) второй раз возвращает исходную — без второй записи в «Обучении» и второй строки J16/J17 |
| **P1.2** J18 дописывается по совпадению текста в любой ячейке | да | строка ищется по **точному ID** оценки или ЧС в «Источнике записи»; тот же текст в описании другой строки её не задевает |
| **P1.3** Окончание фритюра — без причины и без сверки баланса | да | **причина — из списка** (окончание работы — жир остаётся; плановая замена; ухудшение органолептики; результат теста; загрязнение; аварийная замена; другое — с пояснением), пишется в J38. **Сверка баланса**: было во фритюре (переходящий остаток прошлого цикла + залито + долито) против остатка и утилизации. Расхождение — «нужна сверка»: уведомление и кнопка «Фритюр: сверить N» у шеф-повара, су-шефа, ответственного за ХАССП, директора; сверка с пояснением — в цикле и в J38. Допуск расхождения система не подставляет |
| **5.2** Банкетная автоматика — только окно 2 часа | да | банкеты, пропущенные расписанием, догоняются до 3 суток: задача бракеража ставится **«с опозданием»** с просьбой проверить, проведён ли бракераж. Обработанный банкет повторно не берётся |

## Что не меняли
- Подписи — от руки на распечатке, как раньше. Оценку жира, килограммы, причину, допуск вводит человек.
- Предельное время использования фритюрного жира и допуск расхождения баланса не подставляются — источника нормы в комплекте нет.
- Отработанный жир — не складской товар: его вывоз по договору в системе не ведётся; утилизация — в J38 и цикле.

## Права
Фритюр — кто ведёт J38 (повар горячего цеха, повар, шеф-повар, су-шеф); выбор партии со склада — у кого есть право «Склад» или «Канбан». Сверка баланса — шеф-повар, су-шеф, ответственный за ХАССП, директор. Режим осмотра — ответственный за ХАССП, директор. Технический доступ записей не делает.

## Листы
`Фритюр_Циклы_V81` — добавлены колонки: Ключ начала, Ключ окончания, Шаги, Партия масла, Залито, Ед. залитого, Переходящий с прошлого, кг, Долито, кг, Причина, Сверка, Сверил (дописываются сами при первом обращении). Свойство скрипта `MC_HEALTH_ROUTE` — режим осмотра (`shift` по умолчанию, `journal` — прежние вопросы по расписанию).

## Не сделано (архитектура — для решения владельца)
Это перестройка, а не исправление; начинать — после решения владельца. Предлагаемый порядок:

1. **«Моя смена» — один список дел.** Экран `myshift` уже есть, но собирает не всё. Свести в него вопросы журналов, осмотр, фритюр, проверку приборов, обработку яиц, бракераж, просроченное: у каждой карточки — источник, срок, кто должен, одна кнопка. Критерий аудита: обычная смена без открытия журналов вручную.
2. **Единый ответ операции** — «сделано / ждёт / заблокировано / что дальше» вместо всплывающих сообщений: сначала фритюр, осмотр, бракераж, приёмка.
3. **Реестр событий и шагов** (события, шаги, ошибки, связи) — пилот на одном конвейере: приёмка (накладная → партии → входной контроль → маркировка → печать → журнал) с возобновлением по шагам; затем заготовка и банкет.
4. **Надёжность:** блокировки по областям (склад, производство, журналы), распознавание и Диск — вне блокировки.
