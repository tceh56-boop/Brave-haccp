# MON CHEF Restaurant Service — Этап 3: блокнот официанта. Отчёт

Собственность Слепцова Дениса Владимировича.
Разработчик кода — Слепцов Денис Владимирович.

Ветка `claude/restaurant-service`. Решения владельца: касса не подключается — оплату подтверждает сотрудник, сверка по Z-отчёту; правил сервисного сбора и скидок нет — только вручную с причиной.

## 1. Что сделано

| Функция ТЗ | Как сделано |
|---|---|
| Главный экран официанта (§3.1) | Схема зала: свободен / бронь скоро / забронирован / гости / **заказ** (гостей, сумма, сколько готово; свой заказ — с золотой рамкой). Вкладка «Мои заказы» (у администратора — «Заказы»): стол, гости, сумма, на кухне, готово, не отправлено |
| Открытие заказа (§3.2) | «Открыть стол»: гостей (нумеруются 1…N), официант (другого назначает администратор), бронь, комментарий, время. Уникальный OrderID. На столе один открытый заказ, второй — отказ (несколько счетов — внутри заказа) |
| Открыть по брони (§4.5) | Бронь на этот стол и на сегодня → бронь «стол занят», предзаказ переносится в позиции **один раз** (CONVERTED, связь с заказом); повторно по той же брони заказ не открыть |
| Добавление блюд (§3.3) | Из каталога `Блюда` (код блюда), цена — из `Цены_Меню` на сегодня, фиксируется в позиции. Карточка: название, цена и за что, единица, вес/объём, количество, модификаторы, комментарий, гость, курс, кухня или бар. Блюдо на STOP и блюдо без цены не добавляются |
| Единицы и весовые блюда (§3.4) | Цена «порц.» и «шт» — за штуку; «100 г», «кг», «150 мл», «л» — весовое: сумма = цена × вес / база. План → факт после взвешивания, пересчёт по той же цене (стейк 300 → 340 г: 4 500 → 5 100 ₽). Масса в штуки и объём в массу не переводятся |
| Курсы (§3.5) | Настраиваются (`rsCoursesSave`, по умолчанию 4). «Отправить на кухню» — первый ждущий курс готовят, следующие приходят на кухню со статусом «ждёт курса» и не начинаются до «Следующий курс». Ещё: «Отправить курс N», «Отправить выбранные», «Отложить курс» (если кухня его не начала), «Отправить все курсы сразу». Позиция без курса — сразу |
| Отправка на производство (§3.7) | Проверяются все позиции: блюдо в каталоге, цена не изменилась, вес у весовых, STOP/GO (LIMITED — остаток; REVIEW — ждать), действующая версия ТТК. **Хотя бы одна не прошла — не уходит ничего**, официант видит причины («цена изменилась — обновите позицию»). Задания кухни и бара создаются из одного заказа по цеху блюда, с номером стола, версией ТТК, курсом, модификаторами. Повтор с тем же ключом не дублирует (сценарий 9) |
| Отмена позиции | Не отправлена — сразу; на кухне, но не начата — с причиной, задание отменяется, расхода нет. Кухня начала — отмена через кухню с фиксацией расхода (этап 4). Позиция в оплаченном счёте не отменяется |
| Разделение счёта (§3.6) | Один счёт; поровну на N; каждый за себя (по гостям, общее — отдельным счётом); вручную — части по счетам (1 и 1 — пополам; 2 и 1 — две трети и треть, «частичное разделение количества»). Позиция не копируется: счёт ссылается на неё долей. Копейки делятся без потери (1 240 ₽ на 3 = 413,33 + 413,33 + 413,34). Позиции после разделения — «добавить нераспределённое в счёт». Объединение счетов |
| Скидка и сервисный сбор | Вручную, процент или сумма, обязательно с причиной; право `discount` (директор, администратор; руководителю смены — индивидуально). Распределяются по счёту, в котором заданы |
| Оплата | «Оплата подтверждена»: способ (наличные / карта / другое), номер чека для безналичных, сверка суммы с экраном. Право `payment_confirm`. Оплаченный счёт не меняется, переразделить нельзя. **Внутренний счёт — не фискальный чек** |
| Закрытие и отмена заказа | Закрытие — всё распределено и оплачено, ничего не готовится, вес внесён; бронь → «закрыто». Отмена заказа — только если ничего не ушло на кухню, с причиной (администратор) |
| Перенос стола, смена официанта | Администратор: на свободный стол, задания кухни получают новый номер стола |

## 2. Чего на этом этапе нет (по плану ТЗ)

* Экран кухни и бара, статусы «принят / готовится / готово / выдано», «Подано» — этап 4. Задания уже создаются в `ОчередьПроизводства_V1`.
* Списание склада: заказ, отправка, оплата склад **не трогают** (проверено тестом). Списание — в момент производства, этапы 4 и 7.
* Проводка оплаты в журнал продаж J36, экономику и сверка с Z-отчётом — этап 7.

## 3. Права и роли

Новые права: `order_edit`, `order_send`, `order_all`, `bill_split`, `discount`, `payment_confirm`.
Официант: свои заказы, отправка, разделение счёта; чужой заказ — отказ. Подтверждение оплаты официанту, кассиру, руководителю смены — индивидуальным правом от директора. Администратор и директор — всё.

## 5. API

| Функция | Право | Что делает |
|---|---|---|
| `rsOrderOpen({tableId, guests, waiterId?, bookingId?, comment})` | order_edit / order_all | открыть стол (по брони — с предзаказом) |
| `rsOrderGet({id})`, `rsOrderList({siteId, all})` | hall_view / order_* | заказ целиком; открытые заказы |
| `rsMenuForOrder()` | order_* / hall_view | меню: цена и за что, весовое, STOP/LIMITED (без себестоимости) |
| `rsItemAdd`, `rsItemUpdate` (reprice), `rsItemWeight`, `rsItemCancel` | order_edit / order_all | позиции |
| `rsOrderSend({mode: all/course/items, course, itemIds, holdNext})` | order_send / order_all | отправка на производство |
| `rsCourseFire`, `rsCourseHold` | order_send / order_all | «Следующий курс», «Отложить курс» |
| `rsOrderUpdate`, `rsOrderClose`, `rsOrderCancel` | order_edit / order_all | стол, официант, гости; закрытие; отмена |
| `rsBillSplit({mode: one/equal/guests/manual})`, `rsBillAssign`, `rsBillMerge` | bill_split / order_all | счета |
| `rsBillAdjust` | discount | скидка и сбор |
| `rsBillPay({billId, method, receipt, amountKop})` | payment_confirm | подтверждение оплаты |
| `rsCoursesSave({courses})` | hall_manage | курсы предприятия |

Все записывающие функции — с ключом операции, версией записи, журналом транзакций, историей (`СобытияОбслуживания_V1`) и аудитом.

## 7. Ограничения

* Окна ввода количества, веса и причины — системные (`prompt`); на этапе 4 заменю их встроенными формами.
* Мгновенного обновления между устройствами нет: экран заказа обновляется после каждого действия, схема — раз в минуту.
* Выдача готового и «Подано» — после экрана кухни (этап 4).
* Проверено только на стенде; перед пилотом — копия рабочей таблицы.
