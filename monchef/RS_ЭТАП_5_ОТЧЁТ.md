## 1. Гостевое меню (ТЗ §5)

| Функция ТЗ | Как сделано |
|---|---|
| Витрина Reels (§5.1) | `?menu=1` — без входа. Телефон: вертикальная лента на весь экран с «прилипанием», листание медиа блюда касанием слева/справа, видео играет только на экране (без звука), категории, поиск (по названию, составу, категории), фильтры (только доступные, без аллергенов), избранное (на устройстве гостя). Компьютер: каталог карточками в несколько колонок |
| Карточка блюда (§5.2) | Фото / видео / GIF, название, категория, цена и за что, вес или объём, описание, состав, КБЖУ на порцию, аллергены, доступность («сейчас нет» при STOP), «Добавить в заказ» |
| Связь с ТТК (§5.3) | Ничего не вводится повторно: блюда — из каталога `Блюда`, состав — из ТТК (названия продуктов **без граммовок**), КБЖУ — расчёт V73 только по **утверждённым** значениям (хоть одного нет — «КБЖУ не определено», не нули), аллергены — подтверждённые профили (неполные — «уточните у официанта»), цена — `Цены_Меню` на сегодня, уже привязанные «Фото блюд» используются без повторной загрузки |
| Публикация (§5.4) | Редактор `?menuedit=1` (право `menu_publish`): категория для гостя, описание, порядок, загрузка фото/видео/GIF, обложка, порядок медиа, скрыть/удалить, предпросмотр «как у гостя», опубликовать / снять с публикации. Без цены или без медиа — не публикуется. При публикации собирается снимок только из разрешённых полей |
| Медиа внутри интерфейса | Файлы — в закрытой папке Drive владельца «MON CHEF — Меню гостя (медиа)». Наружу не выходят ни ссылки, ни ID файлов: гостевая страница получает файл частями по 2 МБ (`rsPublicMedia`) и собирает его в браузере. Отдаются только медиа опубликованных блюд; скрытые и удалённые — нет. Загрузка — частями по 4 МБ: фото и GIF до 8 МБ, видео до 30 МБ (MP4, WebM, MOV), SHA-256 каждого файла в листе |
| Безопасность (§5.4, §14) | Публичное меню не отдаёт себестоимость, закупочные цены, граммовки и технологию ТТК, партии, сотрудников, ID листов, ID файлов, подразделение и причину STOP (проверено тестом по списку запрещённых слов). Гостевая страница без ключа входа и служебной полосы MON CHEF |
| Заказ гостя (§5.5) | По умолчанию — только просмотр. Директор включает «Гость может отправить заявку официанту». Заявка возможна только по **QR-коду стола** (общая ссылка — просмотр). Заявка **не уходит на кухню**: официант в «Зале» видит её и нажимает «Принять в заказ» (позиции попадают в заказ стола как «не отправлено», дальше — обычная отправка с проверками) или «Отклонить» (с причиной). Защита: повтор с тем же ключом не дублирует, не больше 3 ожидающих заявок со стола и 10 в час, до 30 блюд по 1–20 шт., только опубликованные и не на STOP |
| QR-коды | Каждый стол получает код из 12 знаков; редактор меню печатает QR общего меню и всех столов (SVG, существующая библиотека MON CHEF). Столам, заведённым раньше, коды выдаются одной кнопкой |

## 2. Редактор ролей (решение владельца)

`?roles=1`, право `roles_edit` (директор). Ссылка — в разделах «Настройки» и «Персонал».

* Выбор роли → права по разделам (галочки), отметка «не как по умолчанию», причина обязательна. Изменение действует **сразу** для всех сотрудников с ролью (без повторного входа).
* Своя роль на основе существующей: копируются права, цех и медицинский допуск (если основа — роль кухни). В архив — только когда за ролью нет действующих сотрудников.
* Ограничения: право `system` (технический доступ) не выдаётся никому; у «Директора» нельзя снять `roles_edit`, `grants`, `personnel` (иначе предприятие останется без управления правами).
* История: лист `Роли_Матрица_V1` (каждое изменение — строка; прежняя по той же паре «роль — право» — «заменена»), свои роли — `Роли_Свои_V1`; всё в аудите.
* Права по умолчанию остаются в коде; правки директора накладываются поверх (файл `zz_MonChef_RS_RoleMatrix.gs` загружается после всех модулей и до шлюза, кэш 6 ч, сбрасывается при изменении).
* Ограничение: своя роль не наследует закрепление журналов ХАССП основы — журналы ей открываются индивидуальными правами.

## 6. Ограничения

* Медиа идут через Apps Script: видео 30 МБ — это 15 вызовов по 2 МБ, первая загрузка ролика на медленной сети — несколько секунд. Рекомендация: видео до 10–15 МБ, короткие (до 15 с). Кэш — в памяти страницы, на время просмотра.
* Публикация — снимок: изменения медиа, состава или описания видны гостю после «Опубликовать изменения». Цена и STOP/GO — всегда текущие.
* Заявка гостя — только со стола по QR; предзаказ к брони из публичного меню не делается (бронь — через администратора).
* Drive и квоты Google проверены только на стенде (имитация Drive). Перед пилотом — проверка на копии таблицы с настоящими файлами.
