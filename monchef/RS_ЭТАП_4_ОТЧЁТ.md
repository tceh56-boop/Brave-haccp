## 1. Экран кухни и бара — KDS (ТЗ §7)

Страница `?kds=1` — вкладки «Кухня», «Бар», «Stop/Go» (видны по правам). Ссылки — в разделах «Производство» и «Зал» главного окна.

| Требование | Как сделано |
|---|---|
| Задания из заказа официанта | Приходят автоматически (этап 3). Кухня и бар — раздельно по цеху блюда |
| Цеха | Горячий, холодный, кондитерский, **мясной, рыбный, овощной, заготовочный** — права `shop_*`. Повар видит задания своих цехов, шеф и су-шеф — все (`shop_all`). Новые права цехов директор раздаёт в редакторе ролей. Фильтр по цеху на экране |
| Карточка | Стол (крупно), номер заказа, блюдо и количество, вес, курс, модификаторы и комментарий (выделены), время принятия и кто принял, время ожидания (от 20 минут — красным), приоритет |
| Статусы | НОВЫЙ → ПРИНЯТ → ГОТОВИТСЯ → ГОТОВО → ВЫДАНО; ПРОБЛЕМА, ОТМЕНА, ОЖИДАЕТ КУРСА. Недопустимые переходы отклоняет сервер. Курс, который официант не запустил, готовить нельзя |
| Готовность → официант | «Готово» сразу меняет позицию в заказе на «готово»: официант видит это на схеме зала («готово: N»), в заказе и в уведомлениях |
| Выдача и подача — разные события | «Выдано» (кухня): время, кто выдал, результат. «Подано» (официант): время и кто подал. «Подано» возможно только для готового. Если официант забрал блюдо без кухонного «Выдано», задание закрывается как «забрал официант» |
| Проблема | Повар описывает проблему → позиция «проблема», официант видит текст и согласует с гостем: ждать («Решено, продолжаем» на кухне) или «Заменить» |
| Обновление | Экран раз в 10 с спрашивает метку «данные изменились» и загружает задания только при изменении. Звуковой сигнал при новых заданиях |
| Медицинский допуск | Работа с заданиями — только с действующим допуском: права `kitchen_queue` и `bar_queue` включены в проверку допуска MON CHEF |

## 2. Stop/Go (ТЗ §6)

| Требование | Как сделано |
|---|---|
| Статусы | GO, STOP, LIMITED (остаток), REVIEW (на проверке) |
| Поставить | Блюдо или напиток, подразделение, причина (6 причин из ТЗ), остаток для LIMITED, комментарий; ответственный и время — автоматически |
| Последствия STOP | Новые заказы блокируются — и добавление, и отправка (REVIEW тоже). Залу и директору — уведомление. Гостевое меню сразу показывает «сейчас нет» без раскрытия причины. Запись в аудите и истории |
| LIMITED | Остаток уменьшается при отправке заказа; закончился — автоматически STOP «лимит исчерпан» с уведомлением |
| Восстановить GO | Галочка «проверено: продукты есть, оборудование работает, качество в норме», причина восстановления, кто и когда. REVIEW снимает только ответственный (`stopgo_approve`: шеф-повар, су-шеф) |
| Кухня и бар независимы | Запись — по паре «блюдо — подразделение». STOP бара не трогает кухню; права `stopgo_kitchen` и `stopgo_bar` раздельны |
| Принятые заказы (§6.4) | Не удаляются. При постановке STOP повар выбирает: «выполним» или «не выполним». Во втором случае принятые, но не начатые задания получают статус «проблема — нужна замена», официанту приходит уведомление со списком столов. Официант делает «Заменить»: исходная позиция отменяется без расхода, новая связана с ней («Замена для»), решение гостя записывается в историю |
| История | Лист `СтопГО_V1`: строки не удаляются; действующая запись по паре — «Актуально» |

## 3. Отмена (ТЗ §12, сценарий 8)

* Не отправлена или не начата (НОВЫЙ, ОЖИДАЕТ КУРСА) — официант отменяет сам, расхода нет.
* Кухня уже приняла — официант отправляет **запрос отмены** с причиной; кухня видит его на карточке и уведомление.
* Кухня отменяет: после начала приготовления расход обязателен — «полностью» (по ТТК) или «частично» (с описанием). До начала — можно «расхода нет». Причина обязательна.
* Расход записывается в позицию («Расход при отмене»: что, сколько, версия ТТК, статус на момент отмены, кто, когда, `posted: false`) и проводится по складу на этапе 7. **Сейчас склад не списывается** — это проверено тестом.
* Позицию в оплаченном счёте отменить нельзя.

## 4. Права

Новые права: `kitchen_queue`, `bar_queue`, `stopgo_view`, `stopgo_kitchen`, `stopgo_bar`, `stopgo_approve`, `shop_meat`, `shop_fish`, `shop_veg`, `shop_prep`.

| Роль | Права |
|---|---|
| Повара (горячий, холодный цех, кондитер) | экран кухни своего цеха, Stop/Go кухни |
| Шеф-повар, су-шеф | + все цеха, снятие «на проверке», просмотр зала |
| Официант, администратор | просмотр Stop/Go |
| Директор | всё, включая бар |

Бар до ролей этапа 6 ведут директор, а также администратор и руководитель смены по индивидуальному праву.

## 6. API

| Функция | Право | Что делает |
|---|---|---|
| `rsKdsData({dept, shop, gen})` | kitchen_queue / bar_queue / stopgo_view | задания экрана; `gen` совпал — «то же самое» |
| `rsTicketAct({ticketId, version, action})` | kitchen_queue / bar_queue | accept, start, ready, issue, problem, resolve |
| `rsTicketCancel({ticketId, version, reason, consumption, note})` | kitchen_queue / bar_queue | отмена с расходом |
| `rsItemServe({orderId, itemIds})` | order_edit / order_all | «Подано» |
| `rsItemReplace({itemId, version, code, reason})` | order_edit / order_all | замена |
| `rsStopList`, `rsStopSet`, `rsStopGo` | stopgo_* | Stop/Go |
| `rsGen()` | зал, кухня, бар | метка «данные изменились» |

## 8. Ограничения

* Обновление — не мгновенное: кухня видит новое задание через 10 с, официант видит «готово» через 15 с (ограничение Apps Script, аудит R4).
* Расход при отмене записан, но по складу не проведён — этап 7.
* Звуковой сигнал работает после первого касания экрана: так требует браузер.
* Проверено на стенде; перед пилотом — копия рабочей таблицы и нагрузка с нескольких планшетов.
