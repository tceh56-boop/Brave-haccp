# Stage 108 — Импорт архива ТТК (шаг 2 плана)

Цель: перевести архив технологических карт (561 файл Excel) в систему. Этапы технологии
должны получить типы, а рецептуры — связь с номенклатурой. Система предлагает, технолог
подтверждает. До подтверждения в системе ничего не создаётся.

## Поток

1. **Извлечение** (`tools/ttk_archive/extract_ttk_archive.py`). Apps Script не читает
   `.xls`, поэтому файлы разбираются вне системы:
   ```
   soffice --headless --convert-to xlsx --outdir OUT *.xls     # по каждой папке
   python3 tools/ttk_archive/extract_ttk_archive.py OUT ttk_archive.json
   ```
   Скрипт берёт из карты только исходные данные: шапку, строки сырья и текст технологии.
   Поддерживаются два формата карт: полный (A) и короткий (B), где есть только брутто.
   Если выход не указан, он определяется по одному из источников, а источник записывается
   в карту:
   * колонка «нетто на 1 кг»: выход = нетто / нетто_на_1кг (точно, для ПФ);
   * граммы в названии («Зельц 200 г»);
   * сумма колонки «Вес готового продукта».
2. **Предпросмотр** (`PREVIEW_TTK_IMPORT`, по 40–60 карт за вызов). Сервер:
   * раскладывает технологию на этапы с типами (`parseTechnologySteps_`, общий с ТТК);
   * определяет вид карты: ПФ, если в названии «П/Ф», карта лежит в папке «08 Полуфабрикаты»
     или на неё ссылаются другие карты; иначе блюдо;
   * предлагает режим подачи (`guessServingMode_`) по категории, а при её отсутствии — по этапам;
   * сопоставляет каждую строку сырья: ПФ организации → продукт организации → карта архива →
     «создать продукт»;
   * помечает дубликаты (одинаковое название и состав) и одноимённые карты с разным составом.
3. **Проверка технологом** (`UPDATE_TTK_IMPORT_ROW`). Технолог может исправить название,
   вид, выход, режим подачи, этапы (тип, температуру, время) и сопоставление каждой строки
   (продукт, ПФ, карта архива, новый продукт, «не включать»). Если объект уже есть в
   системе, его можно связать с картой.
4. **Подтверждение** (`CONFIRM_TTK_IMPORT_ROWS`, до 10 карт за вызов из-за ограничения
   времени Apps Script; ПФ обрабатываются первыми). Подтверждение создаёт:
   * блюдо (выход в г) или ПФ (выход в **кг**: себестоимость ПФ считается на единицу
     выхода, а строки архива — в кг);
   * недостающие продукты. Если название однозначно совпадает с записью справочника КБЖУ,
     продукт сразу с ней связывается (`global_product_id`);
   * рецептуру. Процент потерь берётся из разницы брутто и нетто. Строка «порция» на
     другую карту пересчитывается в кг через выход этой карты;
   * черновик ТТК с этапами и режимом подачи. Срок и условия хранения берутся из расчёта
     по нормам; если расчёт невозможен, ставится заглушка «ТРЕБУЕТ ЗАПОЛНЕНИЯ», и такую ТТК
     нельзя отправить на утверждение.

Ошибка в одной карте не останавливает подтверждение остальных: результат возвращается
по каждой карте отдельно.

## Блокеры подтверждения

Пока у карты есть блокер, подтвердить её нельзя:

* не задан выход;
* нет строк сырья;
* строка не сопоставлена (единица «порция», но такой карты нет);
* нет количества в строке;
* строка ссылается на карту архива, которая ещё не подтверждена: «Сначала подтвердите ПФ …».

## Архив «Студии Вкуса Лофт» (ttk.zip): результаты прогона

| | Карт |
|---|---|
| Всего | 560 (549 в формате A, 11 в формате B) |
| Готовы к подтверждению сразу | 207 |
| Ждут подтверждения своих ПФ | 263 |
| Требуют правки технологом | 48 |
| Дубликаты (одинаковое название и состав) | 42 |
| Без текста технологии (ТТК не создаётся) | 217 |
| Выход определён косвенно (подтвердить) | 267 |
| Выход не определяется вовсе | 10 |

Разбор технологии на этапы: 1322 этапа, тепловая обработка найдена в 197 картах.
Среди горячих блюд без найденного нагрева осталось 8 карт, у них в тексте только примечания
вроде «Используется микрозелень».

148 видов «П/Ф» не имеют своей карты в архиве («Чеснок очищенный П/Ф», «Зелень очищенная П/Ф»,
«Семга без кожи и кости П/Ф»). По умолчанию они создаются как продукты (очищенное сырьё).

## Также в этой итерации

* **Режим подачи** (`TTK_VERSIONS.режим_подачи`: HOT, COLD или пусто). Срок годности и ККТ
  учитывают явный выбор, а без него — категорию блюда. Раньше блюдо вида «отварить,
  нарезать, заправить» ошибочно считалось горячим.
* **Пищевая ценность не пишется в ТТК**, если ни у одного ингредиента нет данных КБЖУ.
  Раньше в ТТК попадало «белки 0 г». При неполных данных к тексту добавляется доля массы
  сырья, для которой есть КБЖУ.
* **Разбор технологии стал точнее.** Добавлены «выпекать», «коптить», «томить»,
  «пароконвектомат», «разогреть», «декор» и «на тарелку». Сокращения вроде «сл. масло» и
  «ст. л.» больше не разрывают предложение. Распознаются записи температуры «Т-180*С» и «110 градусов».

## Права

Чтение — модуль `recipes`. Изменения (`PREVIEW`, `UPDATE`, `SKIP`, `CONFIRM`) запрещены
ролям ПОВАР и КЛАДОВЩИК, так же как создание ТТК.

## Проверено

* Сервер (Node, настоящие модули ТТК, рецептур, продуктов, ПФ и блюд, таблицы в памяти):
  * предпросмотр всех 560 карт;
  * подтверждение цепочки «ризотто → сырный ролл → котлета»;
  * блюдо нельзя подтвердить раньше его ПФ;
  * ссылка «Зельц п/ф» в карте «Зельц 200 г» не считается ссылкой на саму себя;
  * связь продукта со справочником КБЖУ, кроме неоднозначных совпадений.
* Интерфейс (Chromium):
  * загрузка JSON архива через выбор файла пачками по 40 карт;
  * выбор и подтверждение 10 готовых карт;
  * подтверждение через карточку;
  * ошибок на странице, связанных с этими изменениями, нет.
