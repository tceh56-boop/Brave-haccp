# ЦЕХ Стандарт — клиентское хранилище (этап SaaS 2)

## Назначение
Этот bootstrap запускается самим клиентом под его Google-аккаунтом. Он создаёт корневую папку и таблицу в Drive клиента, создаёт стандартное дерево папок, явно предоставляет техническому аккаунту поставщика Editor-доступ и регистрирует ресурсы в CONTROL.

## Настройка
1. В CONTROL создайте организацию и выпустите лицензию. Сохраните ключ и секрет (секрет показывается один раз).
2. Клиент создаёт новый проект Apps Script под своим Google-аккаунтом.
3. Скопируйте `TS_TenantBootstrap.gs` в проект клиента.
4. Заполните `CONTROL_URL`, `PROVIDER_EMAIL`, `ENTERPRISE_NAME`, `LICENSE_KEY`, `LICENSE_SECRET`.
5. Запустите `tsTenantBootstrapStart()` и предоставьте Google запрошенные разрешения.
6. Убедитесь, что CONTROL вернул `ownershipVerified: true`.
7. В CONTROL запустите provisioning предприятия.

## Важные ограничения
- Технический аккаунт поставщика получает редакторский доступ к папке и таблице — это осознанное условие для работы серверного Apps Script. Клиент остаётся владельцем созданных ресурсов.
- Bootstrap не выдаёт поставщику доступ ко всему диску клиента.
- При использовании Google Workspace Shared Drives владельца файла может не быть в обычном смысле; текущая проверка намеренно отклонит такой сценарий. Для Shared Drives нужен отдельный режим с проверкой membership/permissions через Drive API.
- Перед продуктивным запуском проверить OAuth scopes, фактического владельца, права доступа и удаление/отзыв доступа на тестовом аккаунте.
- Не публиковать LICENSE_SECRET в клиентском интерфейсе, таблицах или логах.
