## 1. Было (аудит этапа 1, п. 2)
Четыре генератора ППК параллельно:
- **V65** — версии, согласование, график, PDF;
- **V37 «ТТК → ППК»** — свой документ, свои процессы и меры;
- **V35 «Конструктор ППК»** — свои процессы, опасности, ККТ, мониторинг, утверждение;
- **TS2 `GEN_PPK`** — отдельная «ППК» на каждую ТТК.

## 2. Стало
| Генератор | Решение |
|---|---|
| **V65** | Единственный: формирование, проверка, согласование, ввод, график, PDF |
| **V30 (ХАССП)** | Единственный реестр процессов, опасностей, ККТ и мониторинга. V65 читает его |
| **V35 «Конструктор ППК»** | Изменяющие функции (создать, добавить процесс, опасность, меру, утвердить) закрыты: ответ `LEGACY_CLOSED` с объяснением, куда перейти. Данные остаются. «Реквизиты организации» (шапка журналов) не тронуты |
| **V37 «ТТК → ППК»** | Создание документа, добавление меры и утверждение закрыты. ППК по ТТК строится через «Процессы ТТК» → анализ опасностей → V65 |
| **TS2 `GEN_PPK`** | Выпускает **приложение к действующей ППК V65** («Приложение к ППК PPK-… : ТТК «…»»), а не отдельную ППК. Если действующей ППК нет, в основании так и написано. Версии и согласование приложений — прежние |
| **Перенос данных** | `ppkLegacyImport` (право `haccp|haccp_approve`, кнопка «Перенести в ХАССП» в прежних разделах): процессы, опасности и меры V35/V37 копируются в V30. Повтор ничего не дублирует, прежние данные не удаляются. Процесс с тем же названием, что уже есть в ХАССП, не дублируется. Решение «значима» переносится только явное: в V35 «нет» стоит по умолчанию, поэтому решением не считается и опасность переносится как предложение. Пределы переносятся как были, без подстановки. Меры V37 привязываются к процессу ХАССП по операции из текста ТТК (справочник этапа 2); не распознано — процесс «требуется привязка» |

## 3. Мероприятия ППК из карты рисков (этап 3 → V65)
- Значимая опасность операции ТТК, управляемая мерой предприятия (ОППУ/ППУ, без ККТ), даёт мероприятие ППК:
  - операция и ТТК;
  - мера управления и опасность;
  - контролируемые параметры из справочника;
  - журнал (например, `J-KKT-THERMAL`);
  - периодичность «при каждой выработке» — в графике это строка-правило по событию (этап 1);
  - корректирующее действие.
  Одинаковые меры одной операции объединяются.
- Опасность под ККТ отдельного мероприятия не даёт: ККТ и мониторинг V65 берёт из V30, как и раньше. Незначимые опасности и опасности без решения мероприятий не дают; пробелы показывает проверка ППК (этапы 1 и 3).
- Нормативов система не подставляет: «по ТТК и мере управления, утверждённой в анализе опасностей».
- Перед формированием ППК связь ТТК → ХАССП пересчитывается, чтобы ППК отражала действующие ТТК.
- Раздел ППК «ХАССП и ККТ» дополнен связью с ТТК: число операций, опасностей и значимых, по каждой значимой — мера и журнал. Счётчик опасностей больше не учитывает архивные.

## 5. Действия для предприятий с данными в V35/V37
Ответственный за ХАССП открывает «Конструктор ППК» или «ТТК → ППК» и нажимает «Перенести в ХАССП». Затем:
- принимает решения по перенесённым опасностям;
- привязывает меры из процесса «требуется привязка»;
- формирует ППК в разделе «ППК».

Перенос копирует данные и ничего не удаляет; по подтверждению в интерфейсе.
