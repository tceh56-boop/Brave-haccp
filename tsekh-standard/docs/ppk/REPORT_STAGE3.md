## 1. Принцип
Новый реестр опасностей не создан. Решения анализа опасностей по-прежнему хранятся в V30 (`HACCP_Процессы_V30`, `HACCP_Опасности_V30`, `HACCP_ТочкиКонтроля_V30`), их читает генератор ППК V65. Новый модуль `app/TS_HaccpLink.gs`:
- **предлагает** строки в V30;
- **ведёт карту связей** `PPK_HACCP_RISK_MAP` — пересчитываемую, без собственных решений;
- **сообщает о пробелах** проверке ППК.

Решение «значима / не значима» принимает только человек с правом `haccp|haccp_approve` (ответственный за ХАССП или директор; уточнено 12.11.2026 — раньше было только `haccp_approve`, то есть только директор). ЦЕХ AI не утверждает.

## 2. Цепочка
`действующие ТТК` → `TTK_PROCESS_MAP` (этап 2) → производственная модель → процесс V30 → опасности из мастер-справочника поставщика (`TS2_MASTER_HAZARDS_`, по кодам `hazards` справочника операций) → решение человека → мера (ККТ/ОППУ из `HACCP_ТочкиКонтроля_V30` или мера и доказательство в опасности) → журнал контроля (`TS2_OP_JOURNAL_`) → проверка ППК V65.

| Что | Поведение |
|---|---|
| Процесс V30 | Операция из ТТК → процесс `PROC-TTK-<код>` (`DRAFT`, в примечании — какие ТТК). Процессы первичной настройки не дублируются: хранение → `STORAGE`, охлаждение → `COOLING`, приёмка, разогрев, порционирование, отпуск |
| Опасность V30 | Предложение `PROPOSED`, поле «значима» пустое, мера — из справочника. Не предлагается, если на процессе уже есть опасность с тем же текстом (ручная) |
| Решение | `haccpHazardDecide`: «да» — с мерой и доказательством (иначе статус «нет меры»); «нет» — только с обоснованием. Опасность → `ACTIVE`, автор и дата решения, запись в журнале аудита |
| Операция ушла из ТТК | Нерешённые предложения → `ARCHIVED`, процесс → `ARCHIVED`. Решённые остаются, в карте — «пересмотреть». Операция вернулась — предложение возвращается |
| Ручные данные | Процессы, опасности и ККТ, заведённые предприятием, не меняются |
| Карта `PPK_HACCP_RISK_MAP` | Статусы: `NEEDS_DECISION`, `NO_CONTROL`, `CONTROLLED` (ККТ/ОППУ из V30 или мера и доказательство), `NOT_SIGNIFICANT`, `OBSOLETE`. ID строк стабильны, пересчёт идемпотентен |
| Проверка ППК V65 | Новый пункт `TTK_HACCP`: операция действующих ТТК без анализа опасностей, значимая опасность без меры, устаревшее решение — замечание. ППК не утверждается, пока пункт не пройден. Нерешённые опасности показывает существующий пункт ККТ (этап 1) |
| Экран | «Процессы ТТК» → вкладка «Опасности ХАССП»: счётчики, пробелы для ППК, таблица «операция → опасность → мера → журнал», кнопки «Значима» / «Не значима», «Связать с ТТК» |
| Права | Связать — `haccp|haccp_approve|ppk_edit`; просмотр — `haccp|haccp_view|haccp_approve|ppk_view|ppk_edit`; решение — `haccp|haccp_approve` |

## 5. Ограничения
- Опасности предлагаются по типу операции (мастер-справочник поставщика). Опасности, зависящие от конкретного сырья (например, аллергены по составу, рыба — паразиты), автоматически не предлагаются; их добавляют в V30 вручную. Аллергены по составу ТТК — кандидат для этапа 5 или 6.
- ККТ и критические пределы система не создаёт и не подставляет: их заводит предприятие в ХАССП (V30). Карта только показывает, есть ли мера.
- Связь ККТ с опасностью — по `HazardID`. ККТ без опасности считается мерой для всех опасностей своего процесса.
