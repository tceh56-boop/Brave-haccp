## 1. Решение владельца
Филиал = отдельное предприятие со своей таблицей и проектом. Отдельного `LOCATION_ID` внутри таблицы нет: `locationId = organizationId = ENTERPRISE_ID`. Изоляцию филиалов обеспечивает tenant-модель (этап SaaS 5, P1-2). Пункт 12 аудита этапа 1 закрыт.

## 2. Что сделано
| Что | Где | Как |
|---|---|---|
| Единый реестр ТТК | `Блюда` + `Состав` | Второй реестр не создан. Статус ТТК — колонка «Статус ТТК» в конце листа «Блюда»: пусто или `ACTIVE` — действует, `DRAFT` — черновик, `ARCHIVED` — архив. Колонка добавляется один раз и ищется по заголовку |
| Версия ТТК | `ttkVersion` | `код@хеш` (название, выход, технология, срок, цех, состав). Любая правка карты даёт новую версию |
| Справочник процессов | `TTK_PROCESS_DICTIONARY` | 34 операции поставщика в 4 категориях: первичная обработка; тепловая; охлаждение и хранение; дополнительные (су-вид, вакуумирование, ферментация, маринование, посол, фасовка, упаковка, транспортировка). Предприятие добавляет и меняет операции (`ttkProcDictionarySave`), правило проверяется. Новые операции поставщика дописываются, изменения предприятия не затираются |
| Анализатор | `app/TS_TtkProcess.gs` | Уровни: 1 — основное правило (уверенность 0.95); 2 — синонимы (0.8); 3 — разбор по предложениям; 4 — вложенные ТТК; 5 — подсказка ЦЕХ AI по кнопке (только предложение, статус не меняет) |
| Неоднозначность | `REVIEW_REQUIRED` | «или» между операциями одной категории, а также синоним рядом с основным правилом той же категории → уверенность 0.6, проверяет человек |
| Вложенные п/ф | `NESTED` | Ингредиент, совпадающий по названию с другой ТТК (без «п/ф»). В карту пишутся операции прямых п/ф. Глубже — раскрываются при чтении (`_ttkpProcessesOf_`), поэтому лист растёт линейно. Цикл (A→B→A) — замечание `CYCLE`, без зависания |
| Карта процессов | `TTK_PROCESS_MAP` | Ключ строки = ТТК, операция, п/ф и хеш текста. Повторный анализ идемпотентен: решения людей (`CONFIRMED`/`REJECTED`) сохраняются; исчезнувшие операции → `SUPERSEDED` (история не удаляется). Возвращается разница: добавлено и устарело. Запись пакетная: одно чтение и одна запись листа, ID резервируются блоком |
| Черновики | `DRAFT_ANALYSIS` | Анализ черновика по запросу. В производственную модель и ППК не входит |
| «Требуется заполнение ТТК» | `TTK_PROCESS_ISSUES` | `NO_TECHNOLOGY`, `NO_COOLING_STAGE` (тепловая обработка + хранение без охлаждения), `NO_STORAGE_CONDITIONS` (нет температуры хранения), `NO_PARAMS` (у тепловой операции и охлаждения нет температуры или времени), `NO_SHELF_LIFE`, `NO_PACKAGING` (хранимый п/ф без тары), `SEMI_LINK_MISSING` (п/ф без ТТК), `CYCLE`. Устранённые замечания закрываются сами (`RESOLVED`). Система ничего не дописывает в карту и не придумывает значения |
| Производственная модель | `_ttkpActiveModel_` | Операции всех действующих ТТК с количеством карт — вход для этапов 3–4 (ХАССП, ППК V65) |
| V37 на основном реестре | `MonChef_V37_TTK_PPK_BRIDGE.gs` | Аудит этапа 1, п. 11: обход графа читает `Блюда`/`Состав` и вложенные п/ф. Импорт V36 только дополняет отсутствующие коды. Операции берутся из V36, иначе из `TTK_PROCESS_MAP`. Источник в документе — `TTK_REGISTRY` |
| Экран | «Процессы ТТК» (консоль) | Модель, операции на проверку («Верно», «Не то», «Подсказка AI»), замечания, кнопка «Проанализировать все ТТК» |
| Права | шлюз `TS_GATE_` | Анализ — `ttk_edit|haccp|ppk_edit`; просмотр — `ttk_edit|ttk_approve|haccp|ppk_view|ppk_edit`; решение по операции — `ttk_edit|ttk_approve|haccp_approve|ppk_edit`; статус ТТК — `ttk_edit`; справочник — `ttk_approve|haccp_approve`. Все изменения — в журнале аудита |

## 5. Ограничения
- Распознавание — по словарю и правилам. Формулировки вне словаря не распознаются, пока предприятие не добавит правило или не подтвердит подсказку ЦЕХ AI.
- Связь п/ф с ТТК — по совпадению названия. Если название ингредиента расходится с названием карты, появится замечание `SEMI_LINK_MISSING`; нужно исправить название.
- Отключение операции поставщика в справочнике (`active=false`) действует до следующего обновления справочника поставщиком: новые операции дописываются, существующие строки предприятия не меняются.
