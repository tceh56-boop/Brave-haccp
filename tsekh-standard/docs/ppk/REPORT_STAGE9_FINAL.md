## 1. Испытания этапа 9
### 1.1 Сквозной сценарий (`tests/e2e_chain.test.js`)
Одна модель предприятия, каждый шаг читает результат предыдущего:
1. Две ТТК, блюдо с полуфабрикатом → анализ: операции п/ф (запекание, варка, охлаждение) входят в блюдо.
2. Связь с ХАССП: предложения опасностей → решения ответственного → пункт аудита R22 «выполнено».
3. ППК: формирование → мероприятие по жарке из карты рисков с журналом ККТ, раздел «ХАССП и ККТ» со связью с ТТК → ввод.
4. Чек-листы: лабораторное исследование — задача, мера по выработке — по событию → задача с чек-листом на экране «Сейчас».
5. Повар отвечает «Нет» → пункт графика ППК «с отклонением» и нарушение в едином реестре.
6. Устранение → тот же сотрудник подтвердить не может → ответственный подтверждает → источник закрыт.
7. Аудит 360°: R22, R24, R27 выполнены; акт сформирован; история нарушения открывается из аудита.
8. В ТТК добавлена новая операция → R22 снова «нарушение»: операция без анализа опасностей.

## 4. Принципы Мастер-промта, соблюдённые во всех этапах
- **Новые параллельные реестры, генераторы и журналы не создавались.** Новые листы — служебные карты связей и шаблонов: `TTK_PROCESS_*`, `PPK_HACCP_RISK_MAP`, `CHECKLIST_TEMPLATES`. Они пересчитываются и решений не хранят.
- **Нормы не придумываются.** Пределы, режимы, сроки и периодичности берутся только из данных предприятия; если данных нет, система показывает замечание или пробел.
- **AI не утверждает.** ЦЕХ AI только предлагает (операция ТТК); решения по опасностям, проверку устранения, утверждение и ввод ППК выполняет человек с правом. Решения и действия пишутся в журнал аудита.
- **Изоляция.** Филиал = отдельное предприятие со своей таблицей и проектом (решение владельца).
- **Безопасность.** Все новые функции зарегистрированы в шлюзе с правами ролей; инвентаризация точек входа нарушений не находит.
- **Авторская пометка** — в каждом новом модуле и отчёте.
