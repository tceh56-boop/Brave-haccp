## 1. Решение
Новый реестр нарушений не создан. Единый реестр — существующие листы «Журналы_Отклонения» и «Корректирующие_Действия». Их уже читают:
- сводка на главной;
- отчёты, KPI шеф-повара;
- «ХАССП сегодня», готовность;
- подпись журналов;
- пакет проверки и аудит.

Туда же теперь попадают нарушения, которые раньше жили только в своём модуле:

| Источник | Было | Стало |
|---|---|---|
| Экран «Сейчас» (TS2: «Нет», замер вне нормы, ККТ, датчик, пропуски, кейтеринг) | Только `AUTO_RECORDS` DEVIATION. «Устранено» мог нажать любой вошедший, сразу `RESOLVED`, без проверки | Нарушение в реестре (ссылка `TS2:<id>`). «Устранено» — корректирующее действие и проверка другим сотрудником. Статус `AUTO_RECORDS` синхронен |
| Санитария V43 | Свой лист `АвтоАлерты_V43` и свой цикл (этап 1) | Нарушение в реестре (ссылка `V43:<id>`). `v43ResolveDeviation` и `v43VerifyDeviation` идут через общий цикл, статус и история V43 синхронны |
| Задача ППК «Нет» (этап 5) | Пункт графика `DEVIATION` без ссылки | Нарушение в реестре, в пункте графика ППК — `DeviationID` |
| Журнальные нарушения (`recordCorrectiveAction`) | Обычное нарушение закрывал тот же сотрудник, который записал действие | Общий цикл с проверкой |
| Замер холодильника из старого реестра | Модуль температур записывал нарушение, экран «Сейчас» — исключение | Исключение связывается с уже записанным нарушением, дубля нет |

## 2. Жизненный цикл (`app/TS_Violations.gs`)
`открыто` → корректирующее действие → `ожидает проверки` → проверка **другим** сотрудником → `устранено`; не подтверждено — `открыто повторно` (с причиной), затем новое действие.

- Каждое действие и каждая проверка — строка в «Корректирующих_Действиях». Действие, как и прежде, пишется в регулируемый журнал J34. Действия и проверки — в журнале аудита.
- **Критическое нарушение** подтверждает только ответственный за ХАССП. Прежний путь «решение по инциденту с доказательством» (`resolveCriticalIncident`) сохранён и тоже закрывает источник.
- **Режим «самопроверка»** — для предприятия, где ответственный один. Включает только директор (`vioSetVerifyMode`, право `org_edit`, запись в аудите). Действует только для некритических нарушений.
- Нарушения в статусах «ожидает проверки» и «открыто повторно» считаются открытыми везде: сводка, «ХАССП сегодня», подпись журналов, готовность. **Исправлено:** сводка на главной считала открытыми только точный статус «открыто».

## 3. Экран и права
- «Сейчас» — карточка «Ожидают проверки»: где, что, кто устранил, пометка «критическое», кнопки «Подтвердить» и «Не устранено». Без связи карточка просто не показывается, работа смены не прерывается.
- «Устранено» на отклонении сообщает, что теперь нужна проверка другим сотрудником.
- Права:
  - `vioList` — просмотр (ХАССП, производство, санитария, журналы);
  - `vioCorrect` — `haccp|prod_manage|sanitation|journals`;
  - `vioVerify` — `haccp|haccp_approve|prod_manage|sanitation`;
  - `vioSetVerifyMode` — `org_edit`.

## 4. Тесты
- `tests/violations.test.js` — 6 сценариев:
  - исключение → реестр → «ожидает проверки» → тот же сотрудник не подтверждает → другой подтверждает, источник `RESOLVED`;
  - «не устранено» → открыто повторно с причиной → новое действие → закрыто; закрытое не исправляется;
  - санитария V43 через общий цикл;
  - «Нет» по задаче ППК → `DeviationID` в графике;
  - журнальное нарушение: критическое — только ХАССП; самопроверка только для некритических; неверный режим отклоняется;
  - холодильник из старого реестра — без дубля.
- `tests/ttk_process.browser.test.js` — карточка «Ожидают проверки».
- `tests/now_offline.browser.test.js` — экран «Сейчас» без связи по-прежнему работает (тест поймал мою ошибку при разработке, исправлена до коммита).
- Все 22 набора проходят; сборка проходит; инвентаризация точек входа — нарушений нет.

Не проверено: реальный Apps Script; поведение на настоящих листах «Журналы_Отклонения» с историческими статусами.
