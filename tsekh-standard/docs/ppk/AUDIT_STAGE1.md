# Мастер-промт 4.0 — Этап 1. Технический аудит ППК + ТТК + ХАССП + чек-листов

Собственность Слепцова Дениса Владимировича. Разработчик кода — Слепцов Денис Владимирович.

Проверено: исходный код (статический анализ) и автотесты на настоящем коде с имитацией таблиц Google. Реальное развёртывание не проверялось — статический анализ не доказывает работу в Apps Script.

## 1. Что есть в коде

- Файла `Index.html` в проекте нет: интерфейс — `Console.html` (основной) и отдельные страницы (`Journals.html`, `HaccpToday.html`, `Corrections.html` и др.).
- Организации изолированы на уровне развёртывания (свой проект и таблица на предприятие, этап SaaS 5). **Филиалов внутри одной таблицы нет**: в листах ППК, ХАССП и чек-листов нет `LOCATION_ID`.
- Все перечисленные в задании функции защищены шлюзом: сессия + право роли (`createChecklist`, `updateChecklist` — `haccp|prod_manage`; `getChecklists` — `checklists|sanitation`; `addChecklistItem` — только технический доступ; `v65*` — `ppk_*`).

## 2. Карта дублирования (главный результат аудита)

Каждое звено цепочки «ТТК → процессы → опасности → ППК → чек-листы → задачи → факты → нарушения» реализовано в коде несколько раз, параллельно.

| Звено | Реализации в коде | Предложение: единственный источник |
|---|---|---|
| Реестр ТТК | `Блюда` + `Состав` (интерфейс, производство, себестоимость, генератор ТУ/СТО/ППК); `ТТК_Master_V36` + `ТТК_Связи_V36` (импорт с Диска, читает V37) | `Блюда` + `Состав`; V36 — канал импорта, связанный с основным реестром по коду |
| Анализ процессов ТТК | `TS2_Generate._ts2GenFacts_` (10 операций, источник и уверенность, хеш версии ТТК); V37 `ППК_Процессы_V37` (обход графа V36); V30 `HACCP_Процессы_V30` (ручной ввод) | развить `TS2_Generate` в `TTK_PROCESS_ANALYZER` + `TTK_PROCESS_DICTIONARY` и `TTK_PROCESS_MAP` |
| Опасности и меры | V30 `HACCP_Опасности_V30` (поля Significant / ExistingControl / Evidence — решения предприятия); TS2 `TS2_MASTER_HAZARDS_` + `HACCP_CONTROLS_V2`; V35 `CCP_OPRP_V35` | V30 — решения анализа (утверждает человек); TS2 — предложения из ТТК; `PPK_HACCP_RISK_MAP` связывает |
| ППК (документ, версии) | **V65** `ППК_V30`/`ППК_Мероприятия` (версии, согласование, график, PDF); V37 `ППК_Master_V37`; V35 `ППК_V35`; TS2 `GEN_PPK` (документ ППК на каждую ТТК); системный документ TPL-002 | V65 — единственный генератор и версии; V37/V35 — источники мероприятий; ППК по ТТК из TS2 — приложения к ППК V65 |
| Задачи и график | `Code.gs` чек-листы (`DEFAULT_CHECKLISTS`, исполнения); V43 `Санитария_Задачи_V43`; V31 `HACCP_Ожидания_V31`; TS2 `JOURNAL_EXPECTATIONS` (экран «Сейчас», события, офлайн, идемпотентность); V65 `ППК_График` | TS2 `JOURNAL_EXPECTATIONS` — исполнение; V65 график — план; чек-листы — форма исполнения |
| Первичная запись (факт) | TS2 `AUTO_RECORDS` + `MANUAL_MEASUREMENTS` (цепочка хешей); V31 FACT; V43 `ЧеклистФакты_V43` (FactID без общего листа фактов); журналы J01–J53 | `AUTO_RECORDS` как `SANITARY_FACTS` (уже есть FACT_ID, хеш-цепочка, идемпотентность), остальные — ссылки на него |
| Нарушения | TS2 `AUTO_RECORDS` DEVIATION; V43 `АвтоАлерты_V43`; `Corrections.html` (CAPA); V65 `DeviationID` | единый контур нарушений (этап 6), статусы по заданию |
| Нормативная база | V33 `Нормативы_V33` / `Требования_V33` (читает V65); `ЦС_Нормативы` (реестр, ведётся из админ-панели, срок действия) | `ЦС_Нормативы` — документы; `Требования_V33` — пункты, ссылки на документы реестра |

Создавать новые параллельные таблицы в таких условиях нельзя (требование задания) — следующие этапы сводят дубли к одному источнику.

## 4. Тесты этапа
`tests/ppk_stage1.test.js` — 8 сценариев на настоящем коде V65 и V43 (имитация таблиц): ККТ и обоснование; санитарные планы; событийные мероприятия; ввод новой версии; связи `REVIEW`/решения людей; концентрация и исполнитель; жизненный цикл нарушения; просрочка без дублей. На прежнем коде тест падает. Все прежние наборы проходят.

Не проверено: реальный Apps Script, интерфейс в браузере для новых списков (связи, нарушения), производительность на больших листах.
