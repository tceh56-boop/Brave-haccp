# ЦЕХ Стандарт SaaS — отчёт этапа 3

Дата исходной сборки: 11.11.2026  
База: `Установка_ЦЕХ_Стандарт_2026-11-11(1).zip` + Stage 2 tenant bootstrap patch.

## Цель этапа
Связать клиентский bootstrap, provisioning CONTROL и клиентское ядро так, чтобы созданное клиентом хранилище реально использовалось всеми legacy-модулями хранения, без обращения к общим папкам поставщика.

## Найденные P0-разрывы
1. Bootstrap записывал `TS_TENANT_ROOT_ID` в Script Properties своего проекта. Новый bound Apps Script project, создаваемый CONTROL через Apps Script API, не наследует эти Script Properties.
2. `TS2_Core.gs` не читал `TS_TENANT_ROOT_ID` как единственный источник корня; использовал другие параметры.
3. Логический код `ROOT` мог создать вторую папку под клиентским корнем вместо возврата самого клиентского корня.
4. `_tsTreeReady_()` требовал существования `DRIVE_REGISTRY`; при отсутствии листа система могла перейти на legacy-путь и создать папку на диске поставщика.
5. `TS_DriveTree.gs` искал legacy-папки через глобальный `DriveApp.getFoldersByName()` и мог переместить папку другого клиента, доступную поставщику.
6. Старые модули фото, бланков, накладных и ТТК использовали жёстко заданные ID.
7. Импорт ТТК принимал произвольный `folderId`; фотомодуль мог доверять ID файла из реестра без подтверждения его нахождения в клиентском дереве.

## Что исправлено
- Добавлен `TS_TENANT_CONFIG_` в `TS2_Core.gs`: `mode`, `rootFolderId`, `spreadsheetId`, `enterpriseId`.
- CONTROL внедряет конфигурацию в исходник каждого нового клиентского проекта при provisioning и повторно при каждом релизном обновлении.
- Внедрение конфигурации выполняется только после наличия всех обязательных ID; отсутствующая точка внедрения `TS_TENANT_CONFIG_` блокирует provisioning.
- Клиентское ядро читает tenant-конфигурацию из внедрённого исходника; Script Properties bootstrap-проекта больше не являются единственным источником.
- В tenant-режиме отсутствие `spreadsheetId` или root приводит к fail-closed.
- `ROOT` теперь возвращает ровно папку из `rootFolderId`, не создавая дополнительный root.
- `DRIVE_REGISTRY` проверяет `enterpriseId`, ожидаемого родителя и фактическое расположение папки.
- Добавлены логические папки `BLANKS`, `INVOICES`, `TTK_SOURCE`, `TTK_BANQUET`.
- Фото, бланки, накладные, банкетные ТТК и исходные ТТК перенаправлены на логические папки клиента.
- Импорт ТТК блокируется, если выбранная папка находится вне клиентской папки `TTK`.
- Выдача фото блокируется, если файл находится вне папки `PHOTO` клиента.
- Глобальный поиск и автоматическое перемещение legacy-папок отключены в tenant-режиме.
- Обновление релиза клиента без подтверждённых root/table ID блокируется.
- Добавлена требуемая авторская подпись в изменённые исходники.

## Что не подтверждено
- Не выполнялись реальные вызовы Google OAuth, DriveApp, Apps Script API, deployment и web app.
- Не проводился тест на двух независимых реальных Google-аккаунтах.
- Не проверены Shared Drives и доменные политики Workspace.
- Не завершена инвентаризация каждого места, где модули могут получать внешний Drive ID через параметры API, настройки или пользовательский ввод.
- Старые клиентские ресурсы не мигрировались автоматически: это намеренно, чтобы не переместить данные другого предприятия.

## Критерии пилота до массовой установки
1. Два независимых Google-аккаунта A и B; два root folder, две таблицы и два bound Apps Script проекта.
2. В каждом проекте проверить внедрённый `TS_TENANT_CONFIG_` и совпадение ID с карточкой организации в CONTROL.
3. Запустить `_ts2EnsureDriveTree_()` в обоих проектах; проверить `DRIVE_REGISTRY` и реальные родители папок.
4. Загрузить фото, бланк, накладную, исходную и банкетную ТТК в A; убедиться, что все файлы создаются только под root A.
5. Попытаться передать проекту A folder/file ID из B; ожидаемый результат — `TENANT_BOUNDARY`/отказ.
6. Удалить доступ поставщика к root A; приложение должно перейти в контролируемую ошибку доступа, не переключаясь на глобальные папки поставщика.
7. Выполнить backup → release update → проверку версии → rollback drill на тестовом проекте.
8. Только после прохождения всех сценариев разрешить пилотную коммерческую установку.
