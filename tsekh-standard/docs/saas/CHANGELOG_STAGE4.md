# ЦЕХ Стандарт SaaS — этап 4: границы tenant-файлов и контроль целостности

## Что изменено
- В конфигурацию клиентского проекта, внедряемую CONTROL при установке и обновлении, добавлен подтверждённый `ownerEmail`.
- Экспорт PDF листов теперь получает ID таблицы через `_tsTenantSpreadsheetId_()`, а не через потенциально устаревший литерал `SHEET_ID`.
- Перед чтением файла конвейер документов проверяет, что исходник находится внутри `INBOX` текущего предприятия.
- Откат сверки читает rollback-файл только из `SYS_RECON_REPORTS` текущего предприятия.
- Архив событий проверяет ранее созданный архив и перед ротацией убеждается, что архив находится в папке `ARCHIVE` клиента.
- Ошибка перемещения архивной таблицы больше не игнорируется: временный файл отправляется в корзину, операция завершается ошибкой.
- Безопасная выдача файлов через `getSecureFile()` дополнительно проверяет принадлежность файла дереву текущего предприятия.
- Архиватор Mon Chef проверяет исходные файлы внутри tenant root и перемещает архивы через `moveTo()` с проверкой результата.
- Фото-превью из реестра проверяется на принадлежность `PHOTO`.
- Генератор документов и генератор форм журналов больше не оставляют временные документы в корне аккаунта поставщика при неудачном перемещении в tenant-режиме.
- Добавлен `TS4_TenantIntegrity.gs`: авторизованная read-only проверка конфигурации, владельца корня/таблицы, дерева Drive, реестра файлов и резервных копий. Точка входа: `ts4TenantIntegrityCheck(token)`.

## Тесты
- Node.js syntax check всех GS-файлов пакета: 0 синтаксических ошибок.
- Повторно пройден локальный runtime harness Stage 3: root-bound, child-bound, no-provider-root, external-folder-rejected.
- Статические проверки Stage 4: 11/11 PASS (экспорт таблицы, INBOX, rollback, архивы, secure-file, фото-превью, генерация документов/форм, ownerEmail injection).
- Архив ZIP проверен на целостность.

## Границы проверки
- Это локальные статические проверки и тестовые заглушки Node.js. Они не являются проверкой Google Apps Script runtime, OAuth scopes, Drive API, Google Workspace policies или web-app deployment.
- Не выполнялись live-тесты двумя независимыми Google-аккаунтами; не проверены Shared Drives. Текущий bootstrap требует подтверждаемого владельца через `getOwner()`, поэтому Shared Drive пока не считается поддержанным сценарием.
- `MonChef_V70_NormBase.gs` работает с центральной нормативной базой поставщика по отдельному ID — это намеренное исключение из клиентского дерева, предусмотренное архитектурой справочных материалов. Этот доступ должен оставаться только чтением и не должен смешиваться с операционными данными клиента.
- Контроль целостности проверяет до 500 строк `FILES` и последние 200 записей `BACKUP_CATALOG` за один запуск; в результате явно указывает, если проверка ограничена выборкой.
- Перед коммерческим запуском остаётся обязательным пилот на двух тестовых организациях, проверка восстановления backup, отзыва поддержки и обновления клиента без потери его настроек.
