# ЦЕХ Стандарт SaaS — этап 3: единое клиентское дерево Drive

## Суть исправления
- `TS_TENANT_ROOT_ID` теперь является единственным корнем клиентского Drive; код `ROOT` возвращает именно его и не создаёт вложенную папку-клон.
- `_tsTenantSpreadsheetId_()` берёт таблицу из `TS_TENANT_SHEET_ID`; в tenant-режиме отсутствие ID приводит к fail-closed, а не к открытию общей таблицы поставщика.
- Все legacy-ссылки на фото, бланки, накладные, банкетные ТТК и исходные файлы ТТК разрешаются через `DRIVE_REGISTRY` и клиентское дерево.
- В tenant-режиме запрещён глобальный поиск/перемещение папок по имени через `DriveApp.getFoldersByName()`, чтобы не затронуть ресурсы других клиентов. Даже при отсутствующем root режим дерева остаётся включённым и завершается ошибкой, а не создаёт папку поставщика.
- Реестр `DRIVE_REGISTRY` проверяет `enterpriseId` и родителя папки.
- Добавлена проверка принадлежности папок и файлов дереву предприятия; импортёр ТТК не принимает внешнюю папку, фотомодуль не отдаёт файл вне клиентской папки.
- Импортёр ТТК, фотомодуль, UI, триггер аудита и резервное копирование используют tenant-resolver.
- Bootstrap сохраняет `TS_TENANT_MODE=1` и `TS2_ROOT_PARENT_ID`.
- CONTROL внедряет `TS_TENANT_CONFIG_` непосредственно в каждый клиентский проект при provisioning и при обновлении релиза; этим устранена зависимость нового bound-проекта от Script Properties отдельного bootstrap-проекта.
- Обновление клиента без подтверждённых root/table ID блокируется.

## Важные ограничения
- Это исходный кодовый патч; он не применён к Google Apps Script проектам и не прошёл live-тесты Google OAuth/Drive.
- Старые фиксированные ID оставлены как fallback только для legacy-режима. В `TS_TENANT_MODE=1` они не используются для обращения к общим ресурсам.
- Не следует автоматически переносить старые папки поставщика. Миграция существующих клиентских файлов должна выполняться отдельно по явным ID и после проверки владельца/родителя.
- Для уже подключённых клиентов сначала нужен backup и dry-run миграции `DRIVE_REGISTRY`.
- `TTK_SOURCE` — отдельная подпапка внутри клиентской `02_ТТК_и_Меню`; при необходимости исходные файлы ТТК можно загрузить туда.
- Shared Drives требуют отдельной проверки, так как `getOwner()` там может быть недоступен.

## Порядок внедрения
1. Сохранить резервную копию таблицы и проекта Apps Script.
2. Обновить CONTROL из `5_Админ-панель/Control.gs`.
3. Внедрить `TS2_Core.gs`, `TS_DriveTree.gs`, затем клиентские модули из патча.
4. Запустить bootstrap только для нового тестового клиента; проверить Script Properties `TS_TENANT_MODE`, `TS_TENANT_ROOT_ID`, `TS_TENANT_SHEET_ID`.
5. Запустить проверку дерева `_ts2EnsureDriveTree_()` от имени клиентского проекта.
6. Проверить `DRIVE_REGISTRY`: `enterpriseId`, `logicalCode`, `googleId`, `parentGoogleId`.
7. Проверить загрузку/чтение фото, бланка, накладной и ТТК.
8. Убедиться, что файлы создаются только под root клиента.
9. Лишь после успешного пилота переносить действующих клиентов.
