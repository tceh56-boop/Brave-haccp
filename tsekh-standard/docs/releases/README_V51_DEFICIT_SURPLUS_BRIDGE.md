# Mon Chef V51 — Дефицит ↔ Излишек

## Зачем
V48 обнаруживает дефицит банкетного исполнения. V50 знает о существующих излишках. Без связки система может создать задачу «довыпустить», хотя готовый продукт уже лежит на складе.

V51 вводит слой оркестрации:

`V48 дефицит → V50 поиск готового излишка → FEFO-рекомендация → плановый резерв → задача выдачи → остаток дефицита → только остаток требует производства`

## Что важно
- V51 не создаёт второй склад.
- V51 не считает резерв фактическим списанием.
- В карантин/заблокированные партии покрытие не попадает.
- Для готового продукта совпадение должно быть по банкету, продукту и единице измерения.
- Если излишек покрывает только часть дефицита, остаток сохраняется как реальный дефицит.
- Фактическая выдача должна проходить штатной операцией склада/банкетной выдачи с FACT и trace.
- Срок годности не продлевается автоматически.

## Листы
- `Дефициты_Покрытие_V51`
- `Дефициты_Покрытие_Аудит_V51`

## Интерфейс
`?deficitbridge=1&token=...`

Экран показывает исходный дефицит, доступное покрытие излишками и остаток, который всё ещё требует производства/другого действия.

## Серверные функции
- `setupV51DeficitSurplusBridge`
- `v51FindCoverage`
- `v51CoverDeficit`
- `v51BuildDispatchPlan`
- `v51AutomationTick`
- `v51GetDashboard`

## Ограничение текущего этапа
V51 связывает готовую продукцию с банкетным дефицитом. Сопоставление сырья/ПФ с производственным дефицитом требует следующего шага: полноценного перерасчёта потребности по графу ТТК V24 с учётом уже отобранных партий V23 и фактического выпуска V27.
