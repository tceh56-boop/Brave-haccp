# Интеграция с учётными системами — этап 4: R-Keeper 7 по сети

Новый модуль: `app/MonChef_V77_RKeeper.gs`. Экран: «Экономика» → «Кассы и 1С» → карточка «R-Keeper по сети (XML-интерфейс)».

Отчёт R-Keeper из файла загружался и раньше (этап 1). Этот этап забирает продажи прямо с кассового сервера.

## Что нужно у клиента

- Лицензия на XML-интерфейс R-Keeper 7 и включённый XML-интерфейс на кассовом (или справочном) сервере. Это делает дилер R-Keeper.
- Доступ к серверу из интернета (проброс порта или VPN дилера).
- Пользователь и пароль XML-интерфейса (Basic). Пароль хранится в свойствах проекта на сервере ЦЕХ, в экран и аудит не попадает.
- Адрес: `https://<адрес>:<порт>`. Путь `/rk7api/v0/xmlinterface.xml` дописывается сам, свой путь `….xml` можно указать целиком. У кассового сервера обычно самоподписанный сертификат, для него в форме есть галочка (`validateHttpsCertificates: false`).

## Как загружается (`v77RkPull`, `v77RkSyncSystem`)

1. `GetOrderList`: заказы текущего общего дня. Берутся только закрытые (`Finished="1"`).
2. `GetOrder` по каждому закрытому заказу, который ещё не загружался. Ключ строки: `rkeeper:<визит>:<заказ>:<uni строки>`. Уже загруженные заказы повторно не запрашиваются и не задваиваются.
3. Блюда: код, название, количество (в тысячных), сумма (в копейках). Скидки заказа (`Discount`) разносятся по блюдам пропорционально сумме. Бесплатные модификаторы не проводятся, платные идут отдельной строкой. Блюдо с количеством 0 (удалено из заказа) пропускается.
4. Строки идут в общий вход `_v77Ingest_`: сопоставление с ТТК, журнал продаж, списание склада по партиям. Несопоставленные позиции ждут сопоставления.

Кассовый сервер отдаёт только текущую смену, поэтому автозагрузка каждые 30 минут (`MC_SCHEDULE`) включена по умолчанию. Прошлые дни загружаются отчётом R-Keeper из файла. Правило «один день — один источник» не даёт файлу и сети задвоить день.

## Права

`v77RkSave`, `v77RkPull`, `v77RkDisconnect` требуют право `finance_edit`.

## Проверки

- `cloud/test/rkeeper.test.js` прогоняет настоящий код .gs против подменного кассового сервера (Basic, RK7Query). Проверено: адрес и неверный пароль; пароль не уходит в экран; только закрытые заказы; разнесение скидки; бесплатный модификатор и удалённое блюдо; списание склада; повтор без запросов и дублей; расписание; выключенная автозагрузка; 404; отключение.
- `tests/finance_integrations.browser.test.js` проверяет карточку R-Keeper и кнопку сохранения.

На настоящем сервере R-Keeper не проверялось. При первом подключении у клиента нужно сверить суммы одного заказа с чеком: единицы денег (копейки) и количества (тысячные) взяты из описания XML-интерфейса R-Keeper 7, их задают константы `MC_V77_RK_MONEY` и `MC_V77_RK_QTY`.
