# Интеграция с учётными системами — этап 2: iiko по API

Новый модуль: `app/MonChef_V77_Iiko.gs`. Экран: «Экономика» → «Кассы и 1С» → карточка «iiko по API».
Основа — этап 1 (`MonChef_V77_Integrations.gs`): строки из iiko идут в тот же общий вход `_v77Ingest_` — сопоставление с ТТК, журнал продаж, склад по партиям, без дублей.

## Что нужно от клиента

| Что | Где взять |
|---|---|
| Адрес сервера iiko | как в iikoOffice при входе, например `https://kafe.iiko.it` (хвост `/resto` можно не убирать) |
| Логин и пароль | отдельный пользователь iiko с правом работы с API |
| Лицензия API | у дилера iiko: каждое подключение занимает лицензию; ЦЕХ всегда закрывает сессию (logout) |

Пароль не хранится: iiko принимает его SHA-1, в свойствах проекта лежит только он. В аудит и ответы экрана он не попадает.

## Как работает

- Вход: `GET /resto/api/auth?login=…&pass=<SHA-1>` → ключ сессии; выход `GET /resto/api/logout` — всегда, даже после ошибки.
- Продажи: `POST /resto/api/v2/reports/olap`, отчёт `SALES` по учётному дню `[с, по+1)`, без удалённых заказов и позиций.
  Группировка: `OpenDate.Typed`, `CloseTime`, `OrderNum`, `DishCode`, `DishName`, `OrderWaiter.Name`; суммы: `DishAmountInt`, `DishDiscountSumInt` (со скидкой).
  Если на сервере клиента поля называются иначе — их можно переопределить в настройках (`fields`).
- «Загрузить из iiko» — за выбранный период (до 31 дня; по умолчанию вчера и сегодня).
- Автозагрузка (галочка) — каждые 30 минут за вчера и сегодня (`v77IikoSyncSystem` в `MC_SCHEDULE`).
- **Один день — один способ.** Отчёт по чекам из файла и сгруппированный отчёт API дают разные ключи одних и тех же продаж. Поэтому если день уже загружен файлом, API его пропускает (и наоборот): такие строки считаются повторами, экран называет дни.
- Ошибки переводятся в понятные причины: неверный логин или пароль, нет лицензии API, нет права, сервер недоступен. Последний обмен и ошибка видны на экране.

## Проверки

`cloud/test/iiko.test.js` — настоящий код .gs, сервер iiko подменён локальным HTTP-сервером в отдельном процессе: неверный и верный пароль, хранение только SHA-1, тело OLAP-запроса, проведение и списание склада, повторы, «день загружен файлом», расписание, недоступный сервер, отключение.
На настоящем сервере iiko не проверялось — доступа нет. Первое подключение у клиента: нажать «Сохранить и проверить вход», затем «Загрузить из iiko» за один день и сверить с отчётом iikoOffice.
