# Mon Chef V71 — ручная продажа списывает склад по партиям

Продажа вне банкета (Банкеты → Журнал продаж) теперь списывает склад, а каждая списанная партия связывается с продажей.

## Файлы
| Файл | Что делает |
|---|---|
| `MonChef_V71_SaleStock.gs` | что продано (блюдо по ТТК или товар со склада), подбор партий, списание, связи «партия → продажа», лист `Продажи_Списание_V71`, предпросмотр `mcSaleStockPreview`, снятие резервов выданных и закрытых банкетов |
| `MonChef_LegacyBack.gs` | `mcSaleAdd` — проверка названия, номер продажи `SL-…` в строке журнала, списание после записи; `mcSaleData` — товары для подсказки, статус склада у записей |
| `MonChef_V64_EconomyFlow.gs` | себестоимость продажи в зал — по списанным партиям (их цена, FEFO); недостача — строка «на складе не хватило» на проверке; экономика партии учитывает продажу |
| `MonChef_Migration.gs` | шаг 9 «Резервы выданных и закрытых банкетов → сняты» |
| `Console.html` | экран «Журнал продаж»: «Блюдо по ТТК / Товар со склада», «Спишется со склада» до записи, колонка «Склад» |

## Порядок списания
1. **Блюдо по ТТК.** Сначала готовые партии этого блюда, допущенные к выдаче (бракераж, суточная проба, ККТ), по FEFO. Оставшиеся порции — приготовлено под заказ: состав по ТТК, п/ф со склада, недостающий п/ф — до сырья; партии по FEFO.
2. **Товар без ТТК** (вода, соки в упаковке и т. п.) — партии этого товара по FEFO, в единице партии.
3. Не списываются партии: в карантине и с любым статусом, кроме «active»; просроченные на дату продажи; полученные позже даты продажи; заблокированные по отклонению; в резерве банкета.
4. Не хватило — продажа записывается (это факт), списывается доступное, недостача с причиной видна в ответе, на экране, в листе `Продажи_Списание_V71` и в экономике. Остаток уменьшается только на списанное с партий.
5. Названия нет ни в ТТК, ни на складе — продажа не записывается: списать нечего. Блюдо из ТТК нельзя провести «товаром», п/ф — «блюдом».

## Связи
`BATCH —РЕАЛИЗОВАНА_В→ SALE` (вес и единица — сколько списано), `SALE —ПО_БЛЮДУ→ DISH` или `SALE —ПО_ТОВАРУ→ PRODUCT`. Паспорт партии показывает продажу; номер продажи `SL-гггммдд-XXXXXXXX` — в строке журнала продаж (колонка «Источник записи»).

## Резервы банкетов
Раньше резервы продуктов банкета (`Склад_Резервы`) оставались «ACTIVE» после выдачи и закрытия: п/ф на складе считался занятым, выпуск раскладывал ТТК до сырья и списывал его второй раз. Теперь резервы снимаются после полной выдачи (`issueV28Banquet`) и закрытия (`closeV29Banquet`), зависшие — шагом 9 «Миграции данных». Резервы банкетов «в прошлом» без выдачи и закрытия не снимаются: такой банкет надо закрыть.

## Прежние записи
Продажи, записанные до обновления, склад не списывали; в экономике их себестоимость — прежняя оценка (по выпуску или нормативу ТТК). Задним числом система их не списывает.
