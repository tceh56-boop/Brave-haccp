# Интеграция с учётными системами — этап 2б: техкарты и приходные накладные iiko

Новый модуль: `app/MonChef_V77_IikoDocs.gs`. Экран: «Экономика» → «Кассы и 1С» → карточки «Техкарты iiko — сверка с ТТК» и «Приходные накладные iiko — сверка с приёмкой» (видны, когда iiko подключено).

Данные ЦЕХ **не перезаписываются**: ТТК — документ ХАССП с согласованием, приёмка — входной контроль человеком. iiko здесь — источник подсказок и сверки.

## Техкарты (`v77IikoCharts`, только чтение)

- iiko: `GET /resto/api/v2/assemblyCharts/getAll` (действующие на дату), номенклатура `/v2/entities/products/list`, единицы `/v2/entities/list?rootType=MeasureUnit`.
- Блюдо iiko находится в ТТК ЦЕХ по сопоставлению кассы (этап 1) или по точному названию.
- Сравнение брутто на одну порцию (`amountIn / assembledAmount`) в базовых единицах (г, мл, шт). Допуск 5 %.
- Результат по каждому блюду: «нет в ТТК ЦЕХ», «только в iiko: …», «только в ЦЕХ: …», «Свёкла: брутто iiko 200 г, ЦЕХ 250 г (-20 %)», разные единицы.

## Приходные накладные (`v77IikoInvoices`)

- iiko: `GET /resto/api/documents/export/incomingInvoice?from&to` (XML), поставщики `GET /resto/api/suppliers` (XML). Разбор XML — простым разбором по тегам (XmlService в облачной версии нет).
- Сохраняются только проведённые (`PROCESSED`) накладные, в лист `Инт_Накладные_iiko`: одна строка — позиция, ключ `iiko:<id документа>:<номер позиции>`, повторная загрузка не задваивает.
- Сверка с `Приёмка_Партии` по номеру накладной (входящему или внутреннему, без учёта пробелов, знаков и ведущих нулей) и поставщику:
  - **нет приёмки в ЦЕХ** — товар пришёл по iiko, но не прошёл входной контроль (нет партии, срока годности, прослеживаемости);
  - **принята** — с суммой приёмки ЦЕХ и разницей.
- Партии автоматически не создаются.

## Права

`v77IikoCharts` — `finance_view | catalog | ttk_edit`; `v77IikoInvoices` — `finance_edit | receiving | procurement`.
