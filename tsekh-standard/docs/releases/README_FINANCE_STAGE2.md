# ЦЕХ Финансы и Экономика — этап 2: реестр операций и дневные итоги

Основа — этап 1 (исправления ядра V64). Новый модуль: `app/MonChef_V72_FinRegistry.gs`. Первичные листы не меняются,
отдельной финансовой базы нет: реестр указывает на первичные записи, а суммы считает тот же расчёт V64.

## Что появилось

| Лист | Что хранит |
|---|---|
| `Фин_Реестр` | одна запись на первичную операцию (продажа, приёмка партии, событие партии, акт списания, списание со склада, ревизия, выпуск, выдача, банкет, фин. операция, расход, корректировка): ID, тип, дата, организация, точка, источник, автор, статус, версия, сумма, хеш содержания |
| `Фин_Реестр_История` | создание, изменение (было → стало), удаление и восстановление каждой операции |
| `Фин_Итоги_День` | показатели дня: выручка, себестоимость, упаковка, потери по причинам, инвентаризация, расходы, проблемные записи |
| `Фин_Итоги_Блюдо_День` | день × блюдо: продано, выручка, себестоимость |

## Как работает

- **Без дублей.** Ключ записи — тип и номер операции в её первичном листе. Повторная сверка того же события вторую запись не создаёт.
- **История.** Изменилась первичная запись → версия +1 и строка истории. Запись исчезла → статус REMOVED, вернулась → RESTORED.
- **Пересчёт только затронутых дней.** Повторная сверка без изменений ничего не пишет.
- **Закрытый период.** При закрытии (`v64ClosePeriod`) дни периода замораживаются. Изменение операции в закрытом дне попадает в историю с признаком «закрытый период», итоги дня не меняются — исправление только корректировкой.
- **Сверка:** каждые 15 минут (`v72FinSyncSystem` в `MC_SCHEDULE`), после закрытия периода и по кнопке (`v72SyncNow`).
- **Точка = предприятие** (решение 14.11.2026); свод по сети — позже.

## API (право `finance_view`, во всех тарифах)

- `v72SyncNow(json {full?}, token)` — сверить сейчас.
- `v72GetSummary(token, from, to)` — сводка за период из дневных итогов: те же показатели, что `v64GetDashboard().totals`, плюс по дням, по блюдам, потери по причинам, время последней сверки и признак устаревания (> 30 мин).
- `v72GetRegistry(json {from,to,type,status,q,closedChanged,limit}, token)` — реестр с отбором.
- `v72GetOperationHistory(regKey|operationId, token)` — история одной операции.

## Также

- `_v64Totals_` разделён: суммирование + `_v64Derive_` (производные показатели) — чтобы дневные итоги складывались в те же показатели.
- Экраны и отчёты V64/V68 пока работают как раньше. Перевод сводки руководителя на дневные итоги — этап 3 (P&L + CEO Dashboard).
