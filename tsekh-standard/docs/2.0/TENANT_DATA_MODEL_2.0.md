# TENANT_DATA_MODEL_2.0 — модель данных предприятий (тенантов)

## 1. Изоляция

| | Где | Чьё |
|---|---|---|
| Рабочие данные предприятия: ТТК, склад, партии, журналы, сотрудники, медкнижки, документы, аудит | своя таблица Google и своя папка Диска, свой проект Apps Script | предприятия; владелец — аккаунт предприятия |
| Служебные данные: клиент, тариф, лицензия (хеш), подписка, платежи, релизы, обращения, согласия, обезличенная статистика | таблица админ-панели | поставщика |

Одна система предприятия — одна таблица: в рабочих листах нет поля «предприятие», смешать данные двух предприятий в одном листе нельзя. `enterpriseId` (`ENT-…`) приходит из лицензии и записывается в каждую строку реестров 2.0 и в аудит — для сверки выгрузок и резервных копий.

## 2. Идентификаторы

- `enterpriseId` — выдаёт админ-панель (`ENT-<номер клиента>`), неизменен; до подключения лицензии — `ENT-LOCAL`, заменяется при первой проверке.
- Записи 2.0 — `ПРЕФИКС-ГГГГ-000001` (счётчики в `ID_COUNTERS`, под блокировкой). Старые записи получают соответствие в `MIGRATION_MAP`, старые ключи не меняются.

## 3. Что покидает предприятие

| Данные | Куда | Когда |
|---|---|---|
| ключ лицензии (запрос), версия, обезличенные счётчики | админ-панель | при проверке лицензии (раз в 6 ч) |
| метрики `usage.report` | админ-панель | раз в сутки |
| технические ошибки: имя функции, код, сообщение без адресов и длинных чисел | админ-панель | вместе с проверкой лицензии |
| текст обращения в поддержку | админ-панель | когда сотрудник отправил |
| диагностика (см. API_CONTRACT §3) | поддержка | только по ключу, выданному директором, до истечения |
| изображение документа для распознавания, вопрос ассистенту | сервисы распознавания и AI-ассистент (Google Диск, Yandex), если подключены | по действию пользователя |

Персональные данные сотрудников (ФИО, медкнижки, ПИН), ТТК, журналы и документы в админ-панель не передаются.

## 4. Жизненный цикл

1. **Подготовка** — админ-панель создаёт папку, таблицу, проект и развёртывание (шаги в `ENTERPRISE_ONBOARDING`, ресурсы в `ENTERPRISE_RESOURCES`).
2. **Работа** — данные только в контуре предприятия; резервные копии — в его папке `00_Система/backups` с манифестом.
3. **Обновление** — задание обновления ждёт свежей резервной копии предприятия; обновляется только код, данные не трогаются.
4. **Окончание подписки** — льготный период 3 дня, затем только чтение; данные остаются у предприятия.
5. **Запросы по данным** (выгрузка, удаление, передача, исправление) — учитываются в `DATA_REQUESTS` админ-панели; исполняются в контуре предприятия его владельцем или по его поручению.
6. **Удаление клиента** в админ-панели — статус `DELETED`, лицензия отозвана; таблица и папка предприятия остаются у владельца.
