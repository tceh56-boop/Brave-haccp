# ARCHITECTURE_ANALYSIS_2.0 — анализ архитектуры ЦЕХ Стандарт 2.0–2.2

## 1. Исходное состояние (1.x)
- Один проект Apps Script на предприятие: таблица Google — база, `HtmlService` — интерфейс, шлюз `zzz_MonChef_Gate.gs` оборачивает каждую публичную функцию (сессия → право роли → тариф → блокировка → аудит).
- Админ-панель — отдельный проект (`admin/`), своя таблица; лицензия проверяется по HMAC.
- Ограничения: ID без единого формата, нет реестра файлов и папок, нет журнала с защитой от правки задним числом, импорт документов без этапа проверки, массовые изменения без резервной копии, журналы заполняются вручную.

## 2. Целевая схема 2.0: два контура
| Контур | Где | Что хранит | Чего НЕ хранит |
|---|---|---|---|
| Предприятия | таблица + проект предприятия | рабочие данные, реестры 2.0, аудит, резервные копии | данные других предприятий |
| Управляющий | админ-панель поставщика | лицензии (хеш), подписки, платежи, релизы, обращения, согласия, эталоны, обезличенная статистика | ТТК, журналы, сотрудники предприятия |

Связь — только через API `doPost` с подписью HMAC (одноразовый nonce для лицензии, окно 10 мин и запрет повтора подписи для прочих запросов).

## 4. Ключевые решения
1. **Старые листы не меняются.** Адаптеры читают «Блюда», «Состав», «Сотрудники», «Температурные_Объекты»; новые сущности получают ID через `MIGRATION_MAP`.
2. **Идемпотентность везде:** листы, папки, счётчики, пакет настройки, расписание дня, автозаписи (ключ `предприятие|объект|ККТ|событие|версия правила`), предпросмотр генерации (по хешу версии ТТК), платёжные уведомления (хеш события), подготовка предприятия (по шагам).
3. **Никаких выдуманных чисел.** Температура ККТ берётся только из фактического замера (`_tccpState_`, датчик, ручной ввод); без него — `PENDING_CONFIRMATION` и задача на замер. Предел ККТ и срок годности — только из текста ТТК или утверждённого норматива, иначе `REQUIRES_SOURCE`.
4. **Ничего важного без человека:** документы предприятия утверждает роль предприятия (технический доступ — запрещено), конфликты и BLOCKER блокируют утверждение.
5. **Обратимость:** перед импортом, исправлениями, генерацией, миграцией и обновлением — резервная копия; у применённых предложений — данные для отката.
6. **Аудит с цепочкой хешей** (`AUDIT_CHAIN`, `AUTO_RECORDS`): изменение записи задним числом обнаруживается проверкой.

## 5. Ограничения платформы (честно)
- Apps Script не передаёт IP клиента; квоты UrlFetch/Drive; время выполнения 6 мин — массовые операции делятся на порции.
- Автоматическая подготовка проекта и развёртывания требует включённого Apps Script API у владельца админ-панели и свойства `MASTER_SCRIPT_ID`; первый запуск веб-приложения авторизует владелец таблицы (окно Google).
- OCR — встроенный Google Drive; качество зависит от скана, поэтому всё распознанное идёт на проверку.
- Технический ПИН предприятия остаётся под контролем предприятия; согласие на доступ поддержки фиксируется в CONSENTS и журнале аудита.
