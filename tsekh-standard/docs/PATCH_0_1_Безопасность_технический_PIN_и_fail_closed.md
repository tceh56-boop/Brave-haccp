# ЦЕХ Стандарт — security patch 0.1

Собственность Слепцова Дениса Владимировича. Разработчик кода — Слепцов Денис Владимирович

## Изменения

1. Удалён встроенный технический PIN `2258` и fallback-хеш при отсутствии `MC_DEV_PIN_HASH`. Если секрет не настроен, технический вход закрыт.
2. Добавлена однократная функция первичной настройки `mcRbBootstrapDevPin_(pin)`. Её следует запускать вручную владельцу проекта из редактора Apps Script. Принимается ровно 6 цифр; если хеш уже задан, повторная первичная настройка запрещена. В Script Properties сохраняется только хеш.
3. Штатная смена технического PIN через `mcRbSetDevPin` сохранена; доступ к ней требует действующей технической сессии.
4. Удалены прямые проверки старого PIN из `Code.gs`; распознавание старой записи создателя больше не зависит от захардкоженного кода и использует только должность `Создатель системы`.
5. Тарифный шлюз теперь закрывает вызов, если `_tsPlanGate_` отсутствует, выбрасывает исключение или возвращает неожиданный тип.
6. Для записывающих операций ошибка/неожиданный результат `_mcComplianceGate_` также приводит к отказу, а не к пропуску проверки.

## Первичная настройка технического PIN

1. Сделайте копию рабочей таблицы и Apps Script проекта. Не применяйте патч сначала на производственном объекте.
2. В редакторе Apps Script откройте проект ЦЕХ Стандарт и выберите функцию `mcRbBootstrapDevPin_`.
3. Запустите функцию вручную от владельца проекта, передав собственный случайный 6-значный PIN. Не используйте дату рождения, телефон или повторяющиеся цифры.
4. Убедитесь, что в Script Properties появился `MC_DEV_PIN_HASH`, а открытый PIN нигде не записан.
5. Проверьте вход с новым PIN и отказ для `2258`. После входа смену PIN выполняйте штатной функцией `mcRbSetDevPin`.
6. Если редактор Apps Script не позволяет задать аргумент функции напрямую, временно создайте локальную wrapper-функцию в редакторе, вызовите `mcRbBootstrapDevPin_('ВАШ_СЛУЧАЙНЫЙ_PIN')`, выполните её один раз и удалите wrapper сразу после успешного запуска. Не сохраняйте PIN в репозитории или в этом документе.

## Известное ограничение

Изменение fail-closed может блокировать записывающие функции при временном сбое проверки тарифа или допуска. Это ожидаемое безопасное поведение; интерфейс должен показать понятное сообщение и не повторять запись автоматически.
