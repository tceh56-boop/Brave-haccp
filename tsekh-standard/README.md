# ЦЕХ Стандарт

Система управления кухней, ХАССП и производством. Перенесена из MonChef: код, логика, листы таблицы и данные
те же. Изменены название, логотип и оформление. Добавлены подписки, лицензии, охрана труда и нормативы.
Отдельно сделана админ-панель для управления клиентами и подписками.

> Порядок. Контроль. Развитие.

## Состав

| Папка | Что это |
|---|---|
| `app/` | Проект Apps Script системы клиента: 140 файлов `.gs` и 23 страницы `.html` — код MonChef и модули ЦЕХ Стандарт `TS_*.gs`, `TS2_*.gs`, `TS4_*.gs` (подписка, охрана труда, «Готов к работе», датчики, заявки поставщикам, изоляция предприятий, цепочка контроля Мастер-промта 4.0) |
| `admin/` | Отдельный проект Apps Script «ЦЕХ Стандарт Admin» (по ТЗ из документа «Пи» на Диске) |
| `installer/` | Установщик на Google Диск (ищет `TsekhStandard_*.zip` и прежние `MonChef_*.zip`) и `TS_TenantBootstrap.gs` — создание дерева предприятия на Диске клиента |
| `brand/` | Логотипы без фона: горизонтальный, вертикальный, для тёмного фона, знак, иконка приложения |
| `docs/` | Документы комплекта (ДОК_0–ДОК_12): ДОК_1 — структура таблиц, ДОК_8 — функции × роли (собирается `tools/gen_functions_roles.js`), ДОК_11 — описание продукта; `docs/2.0/` — ТЗ 2.0, схема данных и точки входа (собираются автоматически); `docs/saas/` — SaaS: изоляция предприятий, архитектура P1-2, CHANGELOG; `docs/ppk/` — отчёты Мастер-промта 4.0 (этапы 1–9) |
| `tools/` | Сборка: оформление, встраивание экранов, проверка синтаксиса, артефакты 2.0, инвентаризация точек входа, ДОК_8, руководства и комплект установки |
| `tests/` | 26 наборов: Node с имитацией таблиц Google и браузерные (Playwright), без сети |
| `sensors/` | Датчик температуры ESP32 + AHT20 (Winsen, I²C): прошивка и инструкция |
| `dist/` | Архивы для установки и `dist/manuals/` — руководства пользователя по тарифам (PDF) |

## Что изменилось по сравнению с MonChef

1. **Название и логотип.** Везде, где пользователь видит имя, теперь «ЦЕХ Стандарт»: окна, PDF, письма, ярлыки.
   Логотип вырезан из макета без фона. Для входа взят горизонтальный, для меню — версия для тёмного фона,
   для заставки — знак.
   Имена папок на Диске с данными клиента не менялись («Бэкапы Mon Chef», «MON CHEF — Журналы», «MON CHEF — Архив»).
   Иначе система создала бы пустые папки и перестала видеть уже сохранённые журналы и копии.
2. **Оформление по макету.** Тёмное меню с золотой активной плашкой, светлые карточки, шрифты Montserrat и Roboto,
   цвета бренда `#0B0B0B` / `#D4AF37`. Разметка и логика экранов не тронуты: поверх старых цветов лежит слой стилей.
3. **Подписки и лицензия** (`TS_Subscription.gs`). Тариф ограничивает возможности. Шлюз сервера проверяет
   тариф перед каждой функцией, поэтому ограничение нельзя обойти, просто скрыв кнопку.
4. **Охрана труда и нормативы** (`TS_LaborSafety.gs`). Реестр ГОСТ, СанПиН, ТР ТС и документов по охране и условиям
   труда, инструкции по ОТ, должностные инструкции, инструктажи, СОУТ, СИЗ, 11 видов актов с печатью.
5. **Договоры** (`TS_Contracts.gs`), **ЦЕХ AI** и **база отработанных ТТК** (`TS_ProMax.gs`).
6. **«Готов к работе» и экран «Сейчас»** (`TS2_*.gs`). Журналы при выпуске, приёмке, вскрытии, выдаче, суточной пробе,
   санобработке, размораживании, охлаждении и разогреве заполняются по событиям; повару остаются «Да / Нет» и физические замеры.
   Работа без связи, ежемесячный архив журналов, сверка данных по 15 правилам.
7. **Датчики температуры** (`TS_Sensors.gs`, `sensors/`): ручной или автоматический ввод по объекту, одно время проверок,
   сверка с поверенным термометром, контроль «датчик молчит».
8. **Заявки поставщикам** (`TS_SupplierOrders.gs`): заявки по поставщикам, письмо с PDF с почты системы, карточка поставщика.
9. **Реестр нормативов** ведётся поставщиком в админ-панели и приходит клиентам; утрата силы — уведомление и отсчёт времени.
10. **SaaS** (`docs/saas/`): каждое предприятие (в том числе филиал) — своя таблица и свой проект; ядро у поставщика,
    файлы — у клиента (P1-2: выполнение от имени пользователя); проверка границ и целостности (`TS4_TenantIntegrity.gs`).
11. **Цепочка контроля — Мастер-промт 4.0** (`docs/ppk/`): процессы ТТК (`TS_TtkProcess.gs`) → опасности ХАССП
    (`TS_HaccpLink.gs`) → ППК V65 — единственный генератор (`TS_PpkLegacy.gs` закрывает прежние конструкторы с переносом данных)
    → чек-листы и задачи ППК на экране «Сейчас» (`TS_ChecklistGen.gs`) → единый реестр нарушений с проверкой устранения
    другим сотрудником (`TS_Violations.gs`) → санитарный аудит 360° с актом и записями-доказательствами (`TS_Audit360.gs`).
    Нормы и периодичность не придумываются; решения принимает человек, ЦЕХ AI только предлагает.

## Установка системы клиента

Порядок тот же, что у MonChef (`docs/1_Инструкция_по_установке.md`, `docs/ДОК_10_Установка_и_запуск.md`):

1. Соберите архив командой `bash tools/build.sh` или возьмите готовый `dist/TsekhStandard_Application.zip`.
2. Загрузите его в папку установки на Диске, **не распаковывая**. Прежние архивы `MonChef_*.zip` перенесите в «Старые сборки».
3. В проекте-установщике замените код на `installer/TsekhInstaller.gs`. Запустите `installTsekhStandard`
   (прежнее имя `installMonChef` тоже работает).
4. В проекте «ЦЕХ Стандарт» запустите `installAllTriggers` и `installTsTriggers` (ежедневная проверка лицензии).
5. Директор открывает экран **«Подписка»** и вводит ключ лицензии, секрет и адрес админ-панели (их выдаёт админ-панель).
   Пока ключа нет, идёт пробный период: 14 дней, все возможности.

## Установка админ-панели

1. Создайте новый проект Apps Script «ЦЕХ Стандарт Admin». Скопируйте в него файлы из `admin/`.
   Манифест — `admin/appsscript.json`.
2. Запустите `setupAdmin()`. Будут созданы таблица-база со всеми листами, тарифы и первый Super Admin
   (ваш email). Временный пароль появится в журнале выполнения.
3. Запустите `installTriggers()`. Это ежедневные напоминания клиентам и снимок аналитики.
4. Создайте веб-приложение: «Развернуть → Новое развёртывание → Веб-приложение», запуск от «Я», доступ «Все».
   Доступ «Все» нужен, чтобы системы клиентов могли проверять ключ, а ЮKassa и ЮMoney — присылать уведомления.
   Сама панель закрыта паролем и ролями.
5. «Настройки» → платёжная система, реквизиты для счетов, секреты ЮKassa / ЮMoney.
   Адрес webhook для кабинета оплаты показан там же.

## Руководства пользователя по тарифам

`dist/manuals/Руководство_ЦЕХ_Стандарт_<тариф>.pdf` — отдельный документ на каждый тариф (Basic — 85 стр., Basic Pro — 125,
Pro — 132, Pro Max — 135; сборка 12.11.2026). Формат и разделы те же, что в руководстве MonChef (ДОК_9): введение, Часть 1 «Настройка», Часть 2
«Работа персонала», Часть 3, памятка на смену, снимки экранов с нумерованными метками. Снимки перекрашены в оформление ЦЕХ Стандарт,
название и логотип заменены. В каждом документе — только разделы своего тарифа и Часть 4 (подписка, охрана труда, договоры,
ЦЕХ AI, база ТТК, «Сейчас», настройка, ТТК → ТУ/СТО/ППК, данные и сверка, заявки поставщикам, цепочка контроля:
процессы ТТК, опасности ХАССП, чек-листы ППК, нарушения, аудит 360°). Пересобрать: `bash tools/build_manuals.sh` (нужны tesseract-ocr с русским языком и pymupdf).
Полный комплект установки с руководствами: `bash tools/build_kit.sh` → `dist/Установка_ЦЕХ_Стандарт_<дата>.zip`.

## Проверка

```bash
bash tools/build.sh
```

```bash
for f in tests/*.test.js; do node "$f" || echo "FAIL $f"; done
```

`build.sh` проверяет синтаксис всех `.gs` и скриптов в `.html` и прогоняет сквозной тест лицензии:
выпуск лицензии → подпись → тарифы → режим «только чтение» → продление → роли → оплата ЮMoney.
Наборы `tests/` проверяют настоящий код на имитации таблиц Google и экраны в браузере: шлюз и права, изоляцию двух
предприятий, приёмочные сценарии 2.x, заявки поставщикам, нормативы, датчики, всю цепочку Мастер-промта 4.0
(сквозной сценарий от ТТК до акта аудита и нагрузку: 300 ТТК, год графика, 5000 задач, 2000 нарушений), экраны на телефоне.
Работу в настоящем Google Apps Script эти тесты не заменяют: перед запуском кухни пройдите пилот на копии таблицы
(сквозной сценарий — `docs/ppk/REPORT_STAGE9_FINAL.md`, п. 1.1).
