# Stage 114 — Банкетный бланк → «План-меню» (перенос из МонШеф)

Перенос `MonChef_BanquetOcr.gs` (распознавание) и сопоставления с ТТК из `MonChef_BanquetUI.gs`.
Модуль `gas/BanquetOcrCore.gs`.

```
фото/PDF заполненного бланка заказа
  → Yandex Vision (тот же контур, что приёмка, Stage 111)
  → таблица по координатам слов (движок МонШеф)
  → YandexGPT: только опечатки в названиях и шапка; цифры таблицы главнее
  → сопоставление строк с ТТК (блюда организации)
  → черновик: человек проверяет шапку, блюда, количество, исключает лишнее
  → «Создать мероприятие» → «План-меню»: число на бланке — порции ИТОГО, норма на гостя = итого / гостей
  → потребность в сырье и заявка на закупку — существующий «План-меню»
```

## Распознавание (движок МонШеф)

* **Выпрямление.** Слова выпрямляются: наклон определяется по профилю строк, трапеция — по столбику
  цен. Снимок вверх ногами или боком поворачивается.
* **Колонки** определяются по шапке «цена / выход / Кол-во / Сумма» (с учётом ошибок OCR). Если шапки
  нет — по столбикам чисел.
* **Названия и цифры.** Перенесённые названия склеиваются. Ряды цифр проверяются арифметикой
  цена × кол-во = сумма. Названия и ряды цифр сопоставляются по порядку. Пометки справа от суммы
  («фуршет», «детям») прикрепляются к своей строке.
* **Полнота.** Сумма строк сверяется с итогом бланка.
* **Запасные пути.** Без таблицы строки разбирает модель по тексту. Без модели — простой разбор с
  пометкой «черновик, проверьте каждую строку».
* **Ничего не додумывается:** нечитаемое остаётся пустым и сопровождается предупреждением.

### Изменения при переносе

1. **Подвал бланка.** Движок рассчитан на подвал «Всего / Налог / Сервис / Скидка / Итого». Если
   найдено только «Итого», МонШеф отсчитывал низ таблицы на 4 строки вверх и терял последние блюда.
   Теперь строки названий с ценой выше найденной строки подвала остаются блюдами. На проверочном бланке
   было 5 строк из 7 при неподтверждённой полноте, стало 7 из 7, полнота подтверждена. На полном
   подвале поведение прежнее: там выше «Итого» нет строк с ценой.
2. **Шапка.** Одно число в «Месте», «Формате», «Контакте» или «Оплате» (итог, попавший в строку шапки)
   значением не считается — берётся значение, прочитанное моделью.
3. **YandexGPT** вызывается через учётные данные приёмки. Подходят API-ключ и IAM-токен (свойства
   `YANDEX_OCR_API_KEY` / `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`). Если задано
   `INVOICE_LLM_DISABLED=true`, используется только таблица.

## Сопоставление с ТТК

Порядок проверки:
1. точное название;
2. сохранённый синоним (`BANQUET_ALIASES`);
3. название без веса, «п/ф» и знаков;
4. название без ремарок кухни («требуется гарнир», «заказ от…») и типичных ошибок OCR;
5. похожие названия: общие слова, триграммы, основной продукт, вид блюда, состав рецептуры, выход.

Исход сопоставления:
* **Предполагаемое блюдо не подтверждается само.** В интерфейсе оно не предвыбрано: человек нажимает
  «Да, это …» или выбирает блюдо из списка. Мероприятие без этого не создаётся.
* **Выбор человека запоминается синонимом.** В следующем бланке такая строка сопоставится сама.
* **Услуги** («Продление работы») и **примечания** ТТК не требуют.
* **Блюда другой организации** не видны и не выбираются.

## Мероприятие

* **Проверки перед созданием.** Обязательны число гостей и дата, у каждой включённой строки — блюдо и
  количество.
* **Порции.** Одинаковые блюда из нескольких строк складываются. Порции итого — как на бланке, норма
  на гостя — итого / гостей. Пометки («фуршет», «детям») попадают в примечание позиции меню.
* **Однократность.** По одному бланку создаётся одно мероприятие.

## Проверено

Синтетический бланк, самый трудный случай из МонШеф: наклон 3,4°, правый край строки уходит вниз
больше высоты строки. В бланке есть перенос названия, пометки справа, напиток, услуга, шапка и подвал.
Настоящие модули: распознавание приёмки, импорт ТТК, План-меню, BanquetOcrCore.

* **Распознавание.** Таблица и YandexGPT дали все 7 строк с верными цифрами. Полнота подтверждена:
  47 150 ₽ = итог. Шапка прочитана: дата 17.10 с пометкой «год не указан», 18:00, 25 гостей, «Лофт».
* **Сопоставление:**
  * 5 строк подтверждены, «Стэйк из семги» → «Стейк из семги» после правки моделью;
  * «Ассорти мясное (буженина, язык)» — только предложено;
  * «Продление работы» — услуга, ТТК не требуется.
* **Создание мероприятия:**
  * без подтверждения похожего блюда создание отклонено;
  * после «Да, это …» синоним запомнен, мероприятие создано: порции итого 25 / 25 / 6 / 20 / 20 / 10,
    норма на гостя 1 / 1 / 0,24 / 0,8 / 0,8 / 0,4, примечания «фуршет» и «детям»;
  * повторное создание и выбор блюда чужой организации отклонены.
* **Без модели** (HTTP 503) таблица собрана, предупреждение показано.
* **Бланк только с «Итого»:** 7 строк из 7, полнота подтверждена.
* **Chromium (ширина 430 px):** распознавание → проверка → «Да, это …» → создание → состав меню
  мероприятия. Ошибок на странице нет.

**Ограничение проверки.** Движок проверен на синтетическом бланке, построенном по шаблону бланка
ресторана из комментариев МонШеф. Реальных сканов в архиве МонШеф нет. Первые настоящие бланки сверьте
построчно. Предупреждение о полноте («сумма строк ≠ итог бланка») укажет, если строка потеряна.

## После деплоя

Запустите `runAllMigrations()`. Он создаст листы `BANQUET_SCANS` и `BANQUET_ALIASES` и добавит в
`PLAN_MENU_ITEMS` колонки `примечание` и `источник`.
