# ЦЕХ — Stage 34: Universal Period Lock & Controlled Reopening

## Назначение
Централизованно запрещает изменение исторических операций, относящихся к закрытому периоду.

## Правило
`CLOSED` период блокирует мутации, если API передаёт дату операции или идентификатор исторического документа, по которому дата может быть восстановлена.

Не блокируются чтения, мастер-данные и настройки без исторической даты.

## Controlled Reopening
`OPEN request → APPROVED → REOPENED`

Повторное открытие не происходит при одном только создании/утверждении заявки.
Только `REOPEN_PERIOD` переводит закрытие в `REOPENED`.

Каждое действие пишется в audit trail.

## API
- `GET_PERIOD_REOPEN_REQUESTS`
- `CREATE_PERIOD_REOPEN_REQUEST`
- `APPROVE_PERIOD_REOPEN`
- `REOPEN_PERIOD`

## Безопасность
- tenant/location scope;
- причина обязательна, минимум 10 символов;
- повторное открытие не выполняется автоматически;
- после `REOPENED` исторические операции снова доступны согласно обычному RBAC;
- исходные данные периода не изменяются самим механизмом lock/reopen.
