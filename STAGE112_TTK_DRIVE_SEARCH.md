**Разборщик карты** (`parseTtkCardGrid_`) — это перенос `tools/ttk_archive/extract_ttk_archive.py` в Apps Script,
поэтому импорт из JSON и синхронизация с Диском разбирают карты одинаково. Сверка на архиве из 560 карт:
548 XML-таблиц и 12 настоящих Excel-файлов дают тот же результат, что Python-скрипт: название, выход и
его источник, основание, формат, технология, каждая строка сырья и каждое замечание.

## Главное отличие от МонШеф

МонШеф **сам вводил в действие** изменённую карту: создавал «действующую» версию с автором «Импорт».
В ЦЕХе любое изменение из файла проходит проверку технологом:

```
папка Google Диска (подпапки = категории)
  → синхронизация (вручную или ежедневно в 5:00)
  → новая карта        → строка импорта, как из архива
  → изменённая карта   → строка импорта «изменена в файле» с таблицей «было → стало»
                         (название, выход, технология, каждый ингредиент: добавлен / удалён / брутто / нетто / единица)
  → удалённый файл     → отметка «файл удалён»; блюдо, рецептура и ТТК не трогаются
технолог подтверждает изменённую карту
  → рецептура приводится к карте: совпадающие строки обновляются, новые добавляются,
    лишние снимаются (строка остаётся в листе с parent_type = REMOVED — история не теряется)
  → выход блюда/ПФ обновляется
  → новая версия ТТК / техкарты ПФ — ЧЕРНОВИК (если черновик уже есть — обновляется он);
    условия и срок хранения берутся из действующей версии; утверждает технолог
```

## Синхронизация

* **Уже импортированные карты.** Если архив раньше импортировали из JSON, карта на Диске с тем же путём
  и тем же содержанием просто связывается с блюдом или ПФ. Повторно на проверку она не попадает.
* **Отпечаток содержания:** строки сырья, технология и выход (числом). Название в отпечаток не входит:
  его правит технолог. Если файл пересохранили без изменений, это не считается изменением.
* **Повторная правка файла.** Если файл изменили ещё раз до проверки, прежняя строка импорта уходит в
  «пропущена», а проверять нужно новую. Прежняя версия того же файла не делает новую дубликатом.
* **Один пакет импорта.** Пока в пакете папки есть непроверенные карты, новые добавляются в него же.
  Так ссылки блюд на ПФ из той же папки разрешаются внутри пакета.
* **Лимиты Apps Script (6 минут на выполнение).**
  * Ограничения прогона: 4,5 минуты, не больше 20 конвертаций Диском (XML-таблицы архива конвертации не
    требуют). Ежедневный прогон ограничен 2,5 минутами.
  * Неизменённые файлы с той же датой изменения повторно не читаются.
  * Если прогон не закончен, следующий продолжает с места остановки, и интерфейс просит нажать ещё раз.
* **Временные копии** для конвертации создаются в служебной папке «ЦЕХ — временные копии для разбора
  ТТК» и сразу удаляются в корзину.

## Поиск ТТК

`SEARCH_TTK` — один запрос вместо прежнего каталога, который запрашивал версии **по каждому блюду
отдельно** при каждом нажатии клавиши.

* **Где ищет:**
  * название, с учётом опечаток («францзская котлта» → «Французская котлета»);
  * состав (в каких блюдах используется ПФ или продукт);
  * папка/категория;
  * текст технологии.
* **Как работает запрос.** Каждое слово запроса должно найтись хотя бы в одном поле. Совпадения в
  названии стоят выше, у результата показано, где нашлось.
* **Фильтры:**
  * блюда или ПФ;
  * статус: есть утверждённая, черновик, на согласовании, нет ТТК;
  * источник: Google Диск, архив или создана в системе;
  * проблемы: изменены в файле и ждут проверки, не заполнены хранение и срок, нет ТТК, файл удалён с Диска;
  * папка — из найденного.
* **Действия у результата:**
  * открыть ТТК или техкарту ПФ;
  * новая версия;
  * история;
  * «Проверить изменение» — сразу к строке импорта.

## История карты

* Версии ТТК (или техкарты ПФ) с источником, датами создания и утверждения.
* Сравнение любых двух версий. Для ТТК состав берётся из снимка рецептуры версии.
* «Вернуть» — новая версия-черновик, копия выбранной; для блюда можно вернуть и рецептуру. Пока есть
  черновик или версия на согласовании, возврат недоступен: второй черновик запутает технолога.
* Изменения из файлов: первичный импорт, принятые изменения с разницей и изменения, ждущие проверки.
* Состояние файла на Диске.

## Права

`SET_TTK_DRIVE_SOURCE`, `SYNC_TTK_DRIVE` и `RESTORE_TTK_VERSION` закрыты для ролей ПОВАР и КЛАДОВЩИК.
`SET_TTK_DRIVE_SOURCE` закрыт и для КАЛЬКУЛЯТОРА. Поиск и история доступны всем, у кого есть модуль рецептур.

## Проверено

Прогон в Node на настоящих модулях. Google Диск подменён виртуальной папкой поверх настоящего архива
(560 файлов, 12 из них — Excel, требующие конвертации).

* **Разбор.** Сверка с Python-скриптом: 560 из 560 совпадают.
* **Первая синхронизация.** 560 карт, 0 ошибок, 12 конвертаций; повтор ничего не меняет. Статистика
  импорта та же, что из JSON: 207 готовы, 263 ждут ПФ, 48 требуют правки, 42 дубликата.
* **Правка файла котлеты.** Масло 0,030 → 0,025 л, моцарелла → сулугуни. Результат:
  * одна изменённая карта с точной разницей;
  * вид у такой строки менять нельзя;
  * повторная правка до проверки — прежняя строка пропущена;
  * подтверждение: рецептура (изменено 1, добавлено 1, снято 1), ТТК v2 — черновик, v1 по-прежнему
    утверждена.
* **Сравнение и возврат.** Сравнение v1 → v2 показывает те же три изменения. Возврат при черновике
  отклонён; после утверждения v2 возврат к v1 вместе с рецептурой создал v3, моцарелла вернулась.
* **Удаление.** Удалённый файл ПФ отмечен, сам ПФ на месте. Папка «опустела» на 70 % — защита
  сработала, ничего не отмечено. Файлы вернулись — отметки сняты.
* **Архив импортирован раньше из JSON.** 3 карты связаны без повторной проверки. При лимите 5
  конвертаций за прогон отложенные файлы добираются за три прогона.
* **Поиск:** опечатки, состав, вид, источник, категория, фасеты. Чужая организация ничего не видит.
* **Chromium:**
  * каталог одним запросом (прежде — запрос на каждое блюдо);
  * поиск с опечатками и по составу;
  * синхронизация из блока «Google Диск»;
  * фильтр «Изменены в файле» и таблица «Что изменится»;
  * подтверждение, история, сравнение, возврат.

  Ошибок на странице нет.

Прежние прогоны (ТУ, нормы, импорт архива, техкарты ПФ, журналы ККТ, приёмка) проходят. ESLint чистый.

## После деплоя

1. Запустите `runAllMigrations()`. Он создаст листы `TTK_DRIVE_SOURCES` и `TTK_DRIVE_FILES` и добавит
   колонки в `TTK_IMPORT_ROWS` и `TTK_IMPORT_BATCHES`.
2. Владелец скрипта должен иметь доступ к папке. Права `drive` и `script.external_request` в
   `appsscript.json` уже есть.
3. На экране «ТТК → Импорт архива ТТК» вставьте ссылку на папку, нажмите «Сохранить папку», затем
   «Синхронизировать».
4. Ежедневный запуск идёт через существующий диспетчер `tickHourly_` (с 5:00), отдельный триггер не нужен.
   В контрольный список задач `getExpectedTriggerHandlers_` добавлена `ttkDriveSyncTrigger_` — теперь их
   29. Тест этапа 23 `MAIN_TRIGGER_HANDLER_COUNT` ждёт 15; он устарел ещё до этого этапа, было уже 28.
