# Разведка: Restik → ЦЕХ

Дата: 2026-10-06. Цель: добавить в ЦЕХ функции Restik (касса, заказы, CRM, гостевые сервисы),
чтобы получить единую систему автоматизации общепита: экономика + HACCP.
Чистая комната: берём только функции и сценарии. Код, тексты, логотипы и дизайн Restik не используем.
Интерфейс — в дизайн-системе ЦЕХ (токены из `gas/Index.html`).

## Ядро продукта
Заказ (касса / официант) → оплата и чек → списание по техкартам → остатки и себестоимость → отчёты.
Целевая аудитория: малый общепит (кофейни, кафе, бары, пекарни, пиццерии).

## Что уже есть в ЦЕХ (и чего у Restik нет)
Склад с FIFO, инвентаризация, ТТК с версиями, фудкост, закупки, P&L/ABC, импорт продаж,
журналы HACCP, маркировка, прослеживаемость, CAPA, аудит, KPI, роли с PIN.
**Вывод:** ЦЕХ сильнее в производстве и HACCP. Не хватает «фронта»: кассы, заказов, гостей.

## Сценарии
- F01 Продажа на кассе: S05 открыть смену → S01 выбрать блюда (+модификаторы) → оплата → чек → списание по ТТК.
  Края: блюдо в стоп-листе, отмена позиции, возврат, нет связи с ККТ.
- F02 Заказ официанта: S02 стол → блюда → отправить → S01 оплата.
- F03 Стоп-лист: остаток ингредиента ниже нормы ТТК → блюдо автоматически в S04 → скрыто в S01/S02/S07.
- F04 Закрытие смены: S05 → итоги → передача выручки в «Экономику».
- F05 Гость копит бонусы: S01 найти гостя по телефону → начисление → S06.

## Модель данных (предположение)
- Order: id, shift_id, table_id?, waiter_id, status (open|paid|cancelled|refunded), total, created_at
- OrderLine: order_id, dish_id (из ЦЕХ), qty, price, modifiers (json)
- Modifier / ModifierGroup: dish_id, name, price_delta, ttk_delta?
- Shift: id, cashier_id, opened_at, closed_at, cash, card
- Payment: order_id, method, amount, fiscal_ref
- Guest: id, phone, name, bonus_balance; BonusTxn
- Table: id, hall, name
Связь: Order(paid) → Sales.gs createSale_ → списание через Warehouse/ТТК.

## Нельзя клонировать (skip)
Фискальные договоры и регистрация в реестре ПО Restik, их партнёрские подключения эквайринга/ОФД,
их клиентская база. Фискализацию подключаете через свою ККТ/облачную кассу.

## Размер
8 экранов, 5 сценариев, 7 сущностей. Трудное: фискализация 54-ФЗ (нужна интеграция с ККТ/облачной кассой),
работа кассы в Apps Script (скорость и офлайн), одновременные заказы на одном столе.
Оценка: L (квартал) на всё; M (несколько недель) на кассу + стоп-лист + смены без фискализации.
