# MON CHEF — установка и запуск

Сборка от 19.10.2026 · для владельца системы. Время: около 40 минут на установку (лучше вне смены) + настройка данных предприятия.

## Коротко: 12 шагов

Делайте по порядку. Шаги 1–8 — установка, 9–11 — подготовка к работе, 12 — переход с копии таблицы на рабочую.

> **Главное — три вещи, без которых сборка не встанет или сломается.** 
> - **Замените текст установщика** (шаг 4). Прежний установщик на этой сборке останавливается с ошибкой «нет файла App.html»: прежнего интерфейса в сборке больше нет.
> - **Уберите из папки установки файл `MonChefPatches.json`** (шаг 3). Это старые исправления: прежний установщик заменил бы ими новые экраны. Новый установщик его не применяет, но файл лучше убрать.
> - **Дайте новые разрешения** (шаг 6): адрес почты и отправка писем. Без них служебные функции из редактора отвечают «Сессия не найдена», а письма об эскалации не уходят.

## Шаги 1–3. Подготовка

### Шаг 1. Резервная копия рабочей таблицы

1. Откройте рабочую таблицу «Mon Cher — База блюд (из ТТК)».
2. **Файл → Создать копию**. Название: «Резервная копия до обновления 13.10.2026». Папка — любая, кроме «MonChef — установка».

> **Зачем.** Миграция данных (шаг 8) сама делает копию перед изменениями. Ваша копия — вторая страховка, если что-то пойдёт не так на шагах 5–8.

### Шаг 2. Включить Apps Script API

1. Откройте **script.google.com/home/usersettings**.
2. «Google Apps Script API» → **Вкл.** Если уже включено — ничего не делайте.

### Шаг 3. Папка «MonChef — установка» на Google Диске

Это папка, в которой установщик ищет архив. В ней же лежат проект «MonChef», копия таблицы для пилота и резервные копии кода `backup_*.json`.

1. Создайте в ней подпапку «Старые сборки» и перенесите туда все прежние архивы `.zip`.
2. **Файл `MonChefPatches.json` перенесите туда же** (или удалите). В нём исправления к первой сборке: они заменяют главное окно старой версией.
3. Загрузите в папку файл **MonChef_Integrated_Application_1_0_TTK.zip** из папки комплекта «2_Загрузить_на_Диск». **Не распаковывайте** — ни на компьютере, ни на Диске.

> **Какой архив возьмёт установщик.** Самый свежий файл `MonChef….zip` в папке (не в подпапках). Поэтому старые архивы — в «Старые сборки». Сам комплект «Установка_MonChef_….zip» на Диск не загружайте: установщик его не примет.

Папки «MonChef — установка» нет (вы ставите впервые)? Создайте папку с любым названием и запишите её ID — часть адреса после `folders/`. Он понадобится в шаге 4.

## Шаги 4–5. Установщик

### Шаг 4. Обновить текст установщика

Проект-установщик — отдельный маленький проект Apps Script с функцией `installMonChef`. Его создавали при первой установке.

1. Откройте **script.google.com → Мои проекты** и найдите проект, в котором есть функция `installMonChef`. Если его нет — **script.google.com/create** (новый проект).
2. Откройте файл `Код.gs` (или `Code.gs`), выделите весь текст и замените его содержимым файла **MonChefInstaller.gs** из папки «3_Установщик».
3. **Настройки проекта (шестерёнка) → «Показывать файл манифеста appsscript.json»**. Откройте `appsscript.json` и замените его содержимым **installer_appsscript.json**.
4. Вверху `Код.gs` проверьте три настройки (следующая таблица) и нажмите **Сохранить** (значок дискеты).

| Настройка | Значение | Когда менять |
|---|---|---|
| `MC_INSTALL_FOLDER_ID_` | ID папки «MonChef — установка» | Уже указан ID вашей папки. Меняйте, только если ставите в другую папку. |
| `MC_TARGET_SCRIPT_ID_` | `''` (пусто) | Оставьте пустым: установщик сам помнит свой проект «MonChef». ID вписывают, только если проект «MonChef» создавали вручную, без установщика. |
| `MC_USE_SHEET_COPY_` | **true** — пилот | **true**: система работает с **копией** рабочей таблицы — для проверки (шаги 5–11). **false**: с самой рабочей таблицей — шаг 12. |

> **Копия таблицы делается один раз.** При первом запуске установщик скопировал рабочую таблицу («… — пилот MonChef») и дальше использует эту копию. Она не обновляется сама. Нужна свежая копия с сегодняшними данными — перед шагом 5 в проекте-установщике откройте **Настройки проекта → Свойства скрипта** и удалите свойство `MC_SHEET_COPY_ID`.

### Шаг 5. Запустить установку

1. В списке функций вверху выберите `installMonChef` → **Выполнить**.
2. Google попросит разрешения: «Проверить разрешения» → ваша учётная запись. Если появится «Google не проверил это приложение» — **Дополнительные настройки → Перейти на страницу проекта**: это ваш собственный скрипт. Нажмите «Разрешить».
3. Дождитесь «Выполнение завершено» (до 1–2 минут) и откройте **Журнал выполнения**.

В журнале должно быть так:

MonChef установлен (версия N, файлов в проекте: 128). Пропущены как дубли: нет. Исправления: применено 0, уже были 0, не подошли 0. Исправленный архив не создавался. Проект: https://script.google.com/d/…/edit Веб-приложение: https://script.google.com/macros/s/…/exec Таблица (копия для пилота): https://docs.google.com/spreadsheets/d/…/edit **Сохраните себе ссылки** на проект «MonChef» и на веб-приложение. Ссылка на веб-приложение при обновлениях не меняется — это адрес системы для сотрудников. Строка «MonChefPatches.json не применён…» вместо «Исправления: …» — файл исправлений остался в папке. Установка прошла правильно, но уберите файл (шаг 3). Прежний код проекта сохранён в папке установки как `backup_…json`. Шаги 6–7. Проект «MonChef» Шаг 6. Автозапуски и новые разрешения Откройте ссылку «Проект» из журнала (или проект «MonChef» в папке установки). Выберите функцию `installAllTriggers` → **Выполнить**. Google попросит разрешения заново — в этой сборке добавлены два: **«Просмотр адреса электронной почты»** и **«Отправка писем от вашего имени»**. Разрешите. Проверьте: слева **Триггеры** (значок будильника) — 3 триггера. Журнал: `installedTriggers: 3`, `jobs: 34`. **Сделайте шаг 6 до того, как сотрудники откроют систему**Приложение работает от имени владельца. Пока владелец не дал новые разрешения, Google может не пустить сотрудников в приложение и не отправлять письма об эскалации. Других установщиков автозапусков не запускайте: вместе они превышают лимит Google в 20 триггеров. Шаг 7. Свойства скрипта **Проект «MonChef» → Настройки проекта → Свойства скрипта → Добавить свойство**. Свойства хранятся в проекте и при обновлениях не теряются.

> **«У скрипта более 50 свойств… доступен только для чтения».** Google так пишет, если свойств больше 50. Прежние сборки сами создавали служебные свойства — по одному на день (`OP_SEQ_…`) и на каждую задачу расписания (`MC_JOB_LAST_…`) — и через несколько дней владелец уже не мог добавить своё. В этой сборке служебное состояние хранится в нескольких свойствах, а старые убираются сами при шаге 6 (`installAllTriggers`) и раз в день. Если надпись осталась — выберите функцию `mcCleanupScriptProperties` → **Выполнить** и обновите страницу настроек: в журнале выполнения будет «было N, стало M». Ваши свойства (почта, смена, организация, ключи) она не трогает.

| **SHIFT_START**, **SHIFT_END** | 08:00 и 23:00 | Начало и конец смены. От них зависят чек-листы открытия и закрытия смены и время проверок. По умолчанию — 10:00 и 22:00. |

| MC_TZ | Asia/Yekaterinburg | Только если предприятие не в часовом поясе Екатеринбурга. |

| MC_IDLE_MIN | 15 | Автовыход без действий, минут. По умолчанию 15. |

## Шаг 8. Первый вход: миграция, роли, защита

Откройте ссылку на веб-приложение. Введите код технического доступа (2258) — это не сотрудник, а вход для настройки: записей ХАССП под ним не делают.

1. **Настройки → «Миграция данных»**. Сначала создаётся резервная копия, затем данные прежних версий переводятся по шагам. Дождитесь ответа. Журнал — лист «Миграции». Повторный запуск безопасен.
2. **Настройки → «Перенос ролей (этап 10.7)»**. В ответе — сотрудники, кому роль нужно назначить вручную (шаг 9).
3. **Настройки → «🔒 Защита журналов»**. Нажимайте после каждого обновления: защищаются и новые листы.
4. **Настройки → «Код технического доступа»** — смените 2258 на свой код (4–6 цифр). Запишите его и храните отдельно.
5. **Настройки → «Резервные копии» → «Сделать резервную копию»** — точка отката после настройки.

> **Если раньше приложение уже работало.** Попросите сотрудников закрыть и заново открыть систему (или обновить страницу) — иначе на планшетах останутся старые кнопки. Старые закладки (`?revision=1`, `?shift=1` и др.) открывают главное окно на нужном экране.

### Шаг 9. Люди и права

1. **Директор.** Под техническим кодом: **Персонал → «Сотрудники и обучение»** — назначьте сотруднику роль «Директор». Эту роль назначает только технический доступ.
2. **Роли остальным** (директор, под своим ПИН): «Шеф-повар», «Су-шеф», «Повар холодного цеха», «Повар горячего цеха», «Кондитер», «Ответственный за ХАССП», «Администратор» (только банкеты). Каждому — свой ПИН.
3. **Медкнижки** (директор): **HACCP → вкладка «Медкнижки»**. Без действующего медосмотра записи ХАССП от сотрудника не принимаются.
4. **Индивидуальные права** — только при необходимости: **меню → «Права сотрудников»**, с причиной и сроком (ДОК_2, раздел 3).
5. **Не давайте сотрудникам доступ к Google-таблице.** Права MON CHEF действуют в приложении. Кто может редактировать таблицу, меняет листы напрямую — это видно в аудите, но не запрещается.

## Шаги 11–12. Проверка и переход на рабочую таблицу

### Шаг 11. Проверка на копии таблицы

1. **Проверка → «Проверить сейчас»**. Список «чего не хватает» — это шаг 10.
2. Под ПИН шеф-повара, повара и ответственного за ХАССП пройдите обычный день по инструкции для персонала: вход, проверки смены, вопрос о температуре, приёмка накладной, вскрытие партии, выпуск п/ф с замером ККТ, бракераж, печать этикетки.
3. Письма приходят только при эскалации: ВСД не погашен в срок, критическое уведомление осталось без реакции, массовый подбор ПИН. Специально их не вызывайте. В первые дни работы убедитесь, что такие письма доходят на `MC_NOTIFY_EMAIL`.

> **На копии — только проверочные записи.** Записи пилота остаются в копии таблицы и в рабочую не переносятся. Не считайте их журналами ХАССП.

### Шаг 12. Переход на рабочую таблицу

1. Ещё раз резервная копия рабочей таблицы (шаг 1).
2. В проекте-установщике: `MC_USE_SHEET_COPY_ = false` → Сохранить → `installMonChef` → Выполнить. В журнале — «Таблица (рабочая)».
3. Повторите шаги 8–10 **на рабочей таблице**: сотрудники, роли, объекты и настройки хранятся в таблице, а не в программе. Свойства скрипта (шаг 7) повторять не нужно.
4. Раздайте сотрудникам ссылку на веб-приложение и ПИН-коды. Памятку на смену — на кухню.

## Обновления и откат

### Следующие обновления

- Новый архив сборки → в папку «MonChef — установка» (старый — в «Старые сборки») → `installMonChef`. Ссылка на приложение не меняется, прежний код сохраняется как `backup_…json`.
- После обновления: «🔒 Защита журналов» и то, что написано в отчёте к сборке (раздел 0).
- Обновляйте вне смены и попросите сотрудников обновить страницу.

### Откат на прежнюю сборку

1. Верните прежний архив сборки в папку установки так, чтобы он стал самым свежим (загрузите заново), новый — в «Старые сборки».
2. `installMonChef`. Код проекта заменится прежним целиком.
3. Данные таблицы откат не меняет. Если данные повреждены — восстановление из резервной копии (ДОК_6).

> **Откат на сборку до 13.10.2026.** Новый установщик ставит и прежние сборки. Но в них нет прав на почту и адрес владельца: письма об эскалации не уходят, служебные функции из редактора отвечают «Сессия не найдена».

## Если что-то пошло не так

| Что видите | Причина | Что делать |
|---|---|---|
| «В архиве … нет файла App.html» | Запущен прежний установщик | Шаг 4: замените текст установщика. |
| «В архиве … нет файла Code.gs / Console.html» | В папке не тот архив | Загрузите `MonChef_Integrated_Application_1_0_TTK.zip` из папки 2, не распаковывая. |
| «В папке … нет .zip-архива MonChef» | Архив не загружен, переименован или лежит в подпапке | Шаг 3. Имя архива должно начинаться с «MonChef». |
| «Apps Script API … HTTP 403» | API выключен | Шаг 2, подождите минуту, запустите снова. |
| «MonChefPatches.json не применён…» | Старый файл исправлений в папке | Установка прошла. Уберите файл (шаг 3). |
| Функция в редакторе отвечает «Сессия не найдена или истекла» | Не даны новые разрешения или запущено не под владельцем | Шаг 6 под учётной записью владельца, разрешите всё. |
| Сотрудники видят сообщение Google о разрешениях («Authorization is required…») или пустую страницу | Владелец не дал разрешения после обновления | Шаг 6. |
| «Превышено число триггеров» | Запускались старые установщики автозапусков | Ещё раз `installAllTriggers`: он удаляет все триггеры проекта и ставит 3. |
| Свойства скрипта «только для чтения», кнопки «Добавить свойство» нет | Свойств больше 50 (служебные свойства прежней сборки) | Шаг 6 этой сборки или функция `mcCleanupScriptProperties` (шаг 7). |
| Письма не приходят | Нет `MC_NOTIFY_EMAIL` или разрешения на почту | Шаги 6–7. Проверьте папку «Спам». |
| На планшете старые кнопки и экраны | Страница открыта до обновления | Закрыть и открыть заново. |
| «Проверка»: «не готово» | Не внесены данные предприятия | Шаг 10. Это не ошибка программы. |

### Что проверено, а что — только у вас

- Проверено на стенде: копия вашей таблицы в эмуляторе Apps Script и Chromium; установщик — на модели Google (Диск и Apps Script API заменены заглушками): 128 файлов проекта совпали со сборкой, старый файл исправлений не применён; права манифеста сверены с кодом.
- Не проверено: установка на вашем Google, окна разрешений Google, отправка писем, распознавание Yandex и «Меркурий» на настоящих сервисах. Это шаги 5–7 и 11 — делайте их внимательно и смотрите журнал выполнения.
- Итоговый статус готовности — «не готов» (NOT_READY), пока не внесены данные предприятия (шаг 10): это проверка по внутреннему контрольному листу, не заключение Роспотребнадзора.
