# MON CHEF · Кафе

Версия MON CHEF 1.0 (сборка 13.10.2026) для кафе: **банкетов нет**. Спрос задают ежедневные продажи,
поэтому вся логика системы строится от продаж и остатков полуфабрикатов и сырья.

```
продажа (ручной ввод по каждой позиции)
  → списание по ТТК с партий (FEFO; готовые п/ф — первыми, недостающее — до сырья)
  → журналы: продаж J36, история партий (цепочка хешей), прослеживаемость «партия → продажа», журнал склада
  → остатки п/ф и сырья → расход в день, нормы, прогноз на завтра
  → задачи: приготовить п/ф · закупить · использовать партию в первую очередь · списать просроченное
  → экономика: выручка, себестоимость, food cost, расходы по статьям, прибыль
  → аудит предприятия: балл, находки, задачи по критичным
```

## Что изменилось по сравнению с MON CHEF

| Было (ресторан с банкетами) | Стало (кафе) |
|---|---|
| Разделы «Банкеты», «Планирование» (неделя банкетов), «Выдача» | Убраны из меню. Вместо них — **«Продажи»**, **«План по остаткам»**, **«Экономика»**, **«Аудит предприятия»** |
| Журнал продаж J36 заполнялся при выдаче банкета | Каждая продажа кафе пишет строку J36 (источник «кафе · ПР-…») |
| Продукты резервировались и списывались под банкет | Продажа сама списывает продукты по ТТК с партий по FEFO |
| Задачи кухни — из меню банкета | Задачи — из остатков п/ф и сырья против нормы (расход в день) |
| Экономики не было («продажи не заводятся с ценой реализации») | Прайс, выручка, себестоимость, food cost, статьи расходов, P&L, меню-инжиниринг |
| — | Аудит предприятия по 6 разделам, еженедельно автоматически |

Всё остальное (ТТК, склад и партии, приёмка, ХАССП, журналы, санитария, персонал, лаборатория, документы, ВСД, роли)
работает как в MON CHEF. Код банкетов в сборке остаётся, но из интерфейса недоступен. Свойство скрипта
`MC_CAFE_MODE=0` возвращает банкетную главную (меню — в `Console.html`, массив `SECTIONS`).

## Новые экраны

**Продажи → «+ Ввести продажи»** — документ продажи (дата, время, оплата, продавец, чек, смена) и список
позиций меню из прайса: у каждой — цена, количество, скидка; итог считается на лету. Количество можно вводить
за чек или сразу за смену. Отдельной строкой — товар со склада без ТТК (вода, покупной десерт).
При проведении по каждой позиции:
- блюдо раскладывается по ТТК; готовые п/ф берутся со склада первыми, недостающее — до сырья;
- партии уменьшаются по FEFO, просроченные и карантинные не берутся;
- каждая партия получает событие «Продажа (списание по ТТК)» в истории и связь «партия → продажа»
  (в карточке партии — раздел «Реализация»);
- журнал склада — «Расход», источник «Продажа ПР-…»; журнал J36 — строка продажи;
- себестоимость — по средней цене остатка; маржа = сумма − себестоимость;
- **продажа не отклоняется из-за нехватки** (она уже случилась): взятое по партиям списывается, нехватка
  уходит в **«Расхождения»** — их разбирают: «приход не внесён», «недостача», «ошибка ТТК»;
- сторно — с причиной; выручка снимается, себестоимость уходит в потери (блюдо уже приготовлено).

**Продажи → «Прайс»** — цена каждой позиции, себестоимость порции по ТТК, food cost и маржа на лету,
отметка «в продаже». Цена первой продажи позиции без прайса сохраняется в прайс сама.

**План по остаткам** и экран **«Нормы и прогноз»**:
- расход в день — большее из фактического расхода склада и расхода по продажам (разложенного по ТТК) за 14 дней;
- норма по умолчанию: п/ф — минимум 1 и цель 2 дня расхода, сырьё — 2 и 5 дней; любую позицию можно задать вручную;
- задачи (единый центр задач, источник «остатки»):
  - п/ф ниже минимума → «Приготовить п/ф: … — N г» (с проверкой сырья по ТТК п/ф; чего не хватает — в описании и отдельной задачей «Закупить»);
  - сырьё ниже минимума → «Закупить: … — N кг»;
  - партия истекает сегодня/завтра → «Использовать в первую очередь»;
  - просроченная партия с остатком → «Списать просроченную партию»;
  - приоритет — по тому, на сколько часов хватит остатка; нет в наличии — критический;
  - задача закрывается сама, когда остаток восстановлен (например, повар внёс «Приход п/ф»);
  - пересчёт — после каждой продажи, при изменении нормы, кнопкой и раз в час по расписанию;
- прогноз на завтра: блюда (по дню недели) и потребность в п/ф против остатка.

**Экономика** (право «Экономика» — у директора; себестоимость видят и роли с правом «Себестоимость»):
- 23 статьи расходов по умолчанию в 11 группах (персонал, помещение, коммунальные, санитария и ХАССП,
  расходные материалы, маркетинг, банк и эквайринг, налоги…), тип «постоянные/переменные», план на месяц;
- журнал расходов с документом-основанием и сторно вместо удаления;
- отчёт о прибылях и убытках за любой период: выручка → себестоимость по ТТК → валовая прибыль → потери
  от сторно → списания (акты по причинам, просроченные партии) → расходы по группам → операционная прибыль;
  справочно — закупки и точка безубыточности;
- food cost, средний чек, выручка по дням, оплаты, план-факт по статьям;
- меню-инжиниринг (звёзды, рабочие лошадки, загадки, собаки — с рекомендацией) и ABC по выручке.

**Аудит предприятия** — внутренний аудит по записям системы, 6 разделов:

| Раздел | Что проверяется |
|---|---|
| Склад и партии | просроченные партии с остатком, партии без срока, карантин > 2 дней, отрицательные остатки, остаток не сходится с партиями, позиции без цены |
| Продажи и меню | дни без внесённых продаж (с первой продажи; выходные — `MC_CAFE_DAYS_OFF`), открытые расхождения, блюда без состава ТТК, цена ниже себестоимости, высокий food cost позиции, «собаки», доля сторно, пустой прайс |
| Экономика | food cost выше цели, списания > 2 % выручки, операционный убыток, перерасход статей > 10 %, расходы без документа, нет расходов, пропущенные постоянные статьи |
| Задачи и планирование | просроченные задачи, п/ф нет в наличии, много позиций ниже минимума, излишки |
| ХАССП и персонал | контрольный лист готовности к проверке MON CHEF (журналы, медкнижки, ППК, ККТ, лаборатория, поверка…) |
| Целостность учёта | цепочка хешей истории партий, ручная правка листа продаж |

Балл раздела — 100 минус вес находок (критичная 25, высокая 12, средняя 5, низкая 2); итог — среднее.
Каждая находка — что не так, на какую сумму, что сделать и кнопка «Открыть». По критичным и высоким — задачи
директору (одна на находку в неделю). История прогонов — с динамикой балла. Еженедельно в понедельник 7:00 —
автоматически.

## Роли

| Роль | Продажи | План по остаткам | Экономика | Аудит |
|---|---|---|---|---|
| Директор | ввод, прайс | просмотр | полностью | запуск |
| Администратор | ввод, прайс | просмотр | — | — |
| Шеф-повар, су-шеф | ввод, прайс | нормы, задачи | себестоимость и P&L — просмотр | запуск |
| Повара, кондитер | — | задачи, прогноз | — | — |
| Ответственный за ХАССП | — | просмотр | — | запуск |

Новые права — «Продажи кафе», «Экономика», «Аудит предприятия» — выдаются и через «Права сотрудников».
Технический вход продажи не проводит (как и записи ХАССП).

## Настройки (свойства скрипта, необязательно)

| Свойство | По умолчанию | Что задаёт |
|---|---|---|
| `MC_CAFE_MODE` | 1 | 0 — вернуть банкетную главную |
| `MC_CAFE_FC_TARGET` | 35 | цель food cost, % |
| `MC_CAFE_RATE_DAYS` | 14 | за сколько дней считать расход в день |
| `MC_CAFE_PF_MIN_DAYS` / `MC_CAFE_PF_TARGET_DAYS` | 1 / 2 | норма п/ф в днях расхода |
| `MC_CAFE_RAW_MIN_DAYS` / `MC_CAFE_RAW_TARGET_DAYS` | 2 / 5 | норма сырья в днях расхода |
| `MC_CAFE_DAYS_OFF` | — | выходные дни недели для аудита, например `1` (понедельник; 0 — воскресенье) |

## Установка

Как MON CHEF (`docs/1_Инструкция_по_установке.md`), только архив другой:

1. `./build.sh` → `dist/MonChef_Cafe_Application_<дата>.zip`.
2. Загрузить архив **не распаковывая** в папку «MonChef — установка» (прежние архивы — в «Старые сборки»).
3. Установщик `installer/MonChefInstaller.gs` не менялся: `installMonChef`, затем в проекте MonChef — `installAllTriggers`
   (задачи кафе встроены в единый планировщик, новых триггеров не нужно).
4. Заполнить прайс («Продажи» → «Прайс»), статьи расходов и планы («Экономика» → «+ Расход» → «Статьи расходов»),
   провести первый аудит.
