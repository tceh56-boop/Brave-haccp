# Stage 116 — инструкция для персонала, логотип и исправления интерфейса

## Инструкция

`docs/ЦЕХ_инструкция_для_персонала.pdf` — полная инструкция по всем разделам системы.
Формат взят по образцу инструкции MON CHEF: обложка, таблица ролей, «Путь продукта в системе»,
«Где что найти», содержание с номерами страниц. Каждый раздел содержит:
* плашку «Кто / Где»;
* снимки экранов с оранжевыми рамками и номерами, а рядом — шаги с теми же номерами;
* врезки «нельзя / внимание / совет».

В конце — «Нет интернета», «Если что-то пошло не так» (реальные сообщения системы),
«Правила честных записей» и «Памятка на смену».

Снимки сделаны на тестовом стенде: настоящий `Index.html` и все `.gs`, запущенные в эмуляторе
Apps Script. Демо-данные заведены через настоящие действия API под ролями «… Тест».
Генератор лежит в `tools/manual`, сборка — `npm run manual` (см. `tools/manual/README.md`).

## Логотип

Новый логотип «ЦЕХ» в векторе (SVG): башни с зубцами, «голова» с глазами и дуга. Он стоит:
* на экране загрузки — с анимацией;
* на экране входа;
* в шапке и в боковом меню;
* на обложке инструкции.

## Исправления, найденные при съёмке

| Где | Было | Стало |
|---|---|---|
| Меню | Список разделов роли в браузере расходился с сервером: у технолога ХАССП меню было пустым, ни у одной роли не было «Маркировки» и «Охраны труда» | Сервер передаёт модули роли при входе (`modules`), меню строится по ним |
| Вход | После PIN всегда открывалась «Главная»; у повара, кладовщика и лаборанта каждый вход начинался с ошибки «Недостаточно прав» | Открывается «Главная» или первый доступный раздел |
| Главная (шеф-повар) | Блок AI-Директора запрашивался без права — всплывала ошибка | Блок показывается только ролям с доступом |
| Журналы | В строке был код `PPK_FRIDGE_TEMP` | Название журнала, оборудование, норма; записи по времени |
| Задачи | Вид задачи кодом `[cleaning]`; инструктаж — номером документа | Вид по-русски; название инструкции |
| Маркировка | Номер партии вводился вручную (`BATCH-…`); журнал показывался как JSON; даты в формате ISO; кнопка «✓ Проверка этикетки» не срабатывала из-за кавычек | Список партий с остатком и сроком; журнал таблицей; даты `дд.мм.гггг чч:мм`; кнопка работает |
| Охрана труда | Тест нельзя было отправить: кнопка «Проверить тест» ломалась из-за кавычек; результат выводился как JSON; вместо названия инструкции — номер | Тест отправляется, результат «Тест пройден / не пройден», название инструкции и статусы по-русски |
| Закупки | Вместо продукта — `PROD-…` | Название и единица |
| Инвентаризация | Начатая инвентаризация была видна только на устройстве, где её начали | Открытую инвентаризацию точки видят все участники (`GET_OPEN_INVENTORY`) |
| Служебные блоки | «Аварийный центр» и «Карта разбора сырья» с JSON внизу каждого экрана у всех ролей | Только у ролей с модулем «Восстановление» |

Новые действия: `GET_MARKING_BATCHES` (модуль `marking`) и `GET_OPEN_INVENTORY` (модуль `inventory`).

## Замечено, не менялось

* **Бухгалтер может менять технологию.** У роли есть модуль `recipes` и нет запретов на изменение
  и утверждение ТТК и рецептур (у калькулятора такие запреты есть). Решение о правах — за владельцем.
* **AI-Директор — заглушка.** Он понимает ограниченный набор фраз; так и описано в инструкции.
* **Нет офлайн-режима.** Очередь офлайн-операций в интерфейсе не заполняется. В инструкции
  записано, что без связи значения пишут на бумаге и вносят позже.
